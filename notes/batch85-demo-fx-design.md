## 1. 現状とデモの差(実測)

### 1-1. 現在の通常モードの演出

`battle.js` の fx 層(Batch 80)は**前後2枚のスナップショットの差分**から作られる。語彙は
flight / vanish / appear / lp / tap / flip / sink ほか9種で、時間定数は `FX_*_MS` の7件である。

★**差分には「誰が誰を」が無い。**攻撃は「タップが付いた」「HP が減った」という結果としてしか映らない。
これは原則文書 1-6 がまさに指摘した欠落である。

### 1-2. デモが持っているもの

| 演出 | デモのファイル | QTE に在るか |
|---|---|---|
| 攻撃の突進・着弾の揺れと閃光 | `fx/attack.js` | 無い |
| ダメージ・回復・強化の数字 | `fx/feedback.js` / `stage.js popNumber` | 無い(LP の増減表示のみ) |
| 破壊(ひび → 砕け散る破片 → 焦げ跡) | `fx/death.js` | 無い(vanish で消えるだけ) |
| 召喚の着地 | `fx/summon.js` | appear(出現)のみ |
| 呪文の詠唱と着弾 | `fx/spells.js` | 無い |
| パーティクル(canvas) | `fx/particles.js` | 無い |
| 帯テロップ・VICTORY / DEFEAT | `stage.js banner` | 無い(裁定の範囲で一部表示のみ) |
| 操作: ポインタでのドラッグ・矢印で攻撃対象を選ぶ・長押し拡大・タップ | `view/input.js` | ★HTML5 DnD(タッチ不可)と右クリック拡大 |

### 1-3. ★デモと QTE がすでに同じ規則を持っていること

- ★★**演出層は `position: fixed`、祖先に `transform` / `filter` を付けない。**
  デモの README 注意点と、84b 7章(`filter: brightness()` で fx 層がずれた)は同じ事実である。
  ★**84b の「沈め」は `opacity` のままにすること。**
- デモの `timing.reduced` は QTE の `fxAllowed()` に対応する。★**移植時は `fxAllowed()` に一本化する**(正を2つにしない)。
- デモのルールは「瞬時に確定し、画面が後から追いかける」。QTE の方式B と同じ形である。

## 3. 85a —— サーバに出来事を足す

### 3-1. 形

```java
public record GameEvent(String kind, String seat, String src, String dst,
                        Integer amount, Integer after, CardFace face) { }

public record GameStep(int seq, String logLine, GameView view, List<GameEvent> events) { }
```

| kind | src | dst | amount / after | face |
|---|---|---|---|---|
| `ATTACK` | 攻撃側 instanceId(リーダーは `leader:A`) | 対象(同上) | — | — |
| `DAMAGE` | 発生源(分かる場合) | 受けた側 | 量 / 残り HP | — |
| `HEAL` | 同上 | 同上 | 量 / 残り HP | — |
| `DESTROY` | — | 破壊された側 | — | — |
| `SUMMON` | 手札から出たなら手札位置 | 出た instanceId | — | 公開面 |
| `CAST` | — | — | — | ★公開面(使った瞬間に公開情報) |
| `DRAW` | — | — | 枚数 | ★**本人にだけ面を載せる** |
| `TURN` | — | — | — | — |
| `GAME_OVER` | — | 勝者の席 | — | — |

★★**視点ごとの切り落としは `StepRecorder` が視点ごとにビューを作る場所で行う**(原則 1-3)。
相手の `DRAW` は枚数だけ届き、面は構造的に届かない。

### 3-2. 取り付け点(母集団 —— 2026-09-30 に 84a のコードで実測)

★**変更は `GameActions` の入口に集める。**`CardEffectRegistry`(6232行)は1行も変えない。

| 出来事 | 取り付け点 | 呼び出し元の数(実測) |
|---|---|---|
| DAMAGE(ミニオン) | `GameActions.damageMinion` / `dealCombatDamage` | 17+1 / 3+1 |
| DAMAGE(リーダー) | `GameActions.damageLeader` | 24+3 |
| HEAL | `GameActions.healLeader`、`GameService` の `.heal(` 1箇所 | 18+3 / 1 |
| DESTROY | `GameActions.destroyMinion` | 25+5+2 |
| DRAW | `GameActions.drawCards` / `drawCardsWithoutOpponentWatchers` | 56+4+6 |
| ATTACK | `GameService.attack` / `leaderAttack` | 2 |
| SUMMON / CAST | `GameService.playCard` / `specialSummon` / `specialSummonFromGrave` / `summonFromGrave` | 4 |

★`MinionInstance.takeDamage` の呼び出しは `GameActions` の1箇所だけである —— ★**入口を塞げば漏れない**ことを確かめてある。
★★**呼び出し元(約170件)は1行も変えない。**入口の中で記録する。
★★★**通常モードの `addLog` の呼び出し 243件(effect 131 / game 112。84a と一致)も1行も変えない**(裁定68)。

### 3-3. 段との結び付け

`GameRoom` に出来事の溜めを持たせ、★**`addLog` が段を切る瞬間に、溜まった出来事をその段へ渡して空にする。**
すなわち「ログ行 X の前に起きた出来事は段 X に属する」。
最後の `addLog` の後に起きた出来事は最終状態の段に付ける。

★★**サーバが畳んだ段(裁定370・`StepRecorder.LIMIT` = 8)の出来事は落とす。**
最終状態には結果が載っているので、畳んだ段の破壊は「演出なしで消えている」ことになる。
これは畳みの定義どおりであり、新しい規則ではない(Q4 で確認する)。

### 3-4. 手動モード

`manual/` 配下は `GameActions` を通らない。★**手動モードは構造的に巻き込まれない**が、JUnit で「手動の配信に `events` が載らない」ことを番人にする。

## 4. 85b —— 演出の移植

### 4-1. ファイル

- ★**新設 `static/js/battle-fx.js`**(デモの `fx/` 9ファイルを1本の IIFE に束ね、`window.QteFx` で公開する)。
  QTE は ES モジュールを使っていないので、形をそちらへ合わせる。
- `battle.js` 側は**出来事 → 演出の対応表**(デモの `director.js` に相当)だけを持つ。
- `battle.css` に演出層のスタイルを足す。★**盤面とカードの見た目のクラスは持ち込まない**(0章)。

### 4-2. 差分演出との住み分け

★★**出来事が語る対象は、差分演出を抑止する。**
例: `DESTROY` が来たミニオンは vanish を出さず、砕け散る演出だけを出す。
★**出来事が無い変化(マナ・墓地・消滅・禁忌の出入り)は、いまの差分演出のまま残す。**

### 4-3. 段の長さ

★**新しい表は作らない**(84b 2-1)。デモの演出も `fxRegister` を通して長さを登録させ、段の長さは自動で追随させる。
デモの `setSpeed` は持ち込まない(QTE の速さの正は `stepTune()` の1箇所である)。

### 4-4. 音

★既存の SFX(`SFX_VERSION` = 1)の鳴らしどころは変えない。新演出と音のずれは実機確認に回す。
