## 1. 何を作ったか

単層の `linear-gradient` を、**3種類の層の重ね**へ置き換えた。画像は使っていない
(25 で画像を廃止した経緯を維持する。純CSSのみ)。

| 層 | 役割 |
|---|---|
| 斜めの光沢 | 左上から右下へ 115度で走る帯。カードが「面」であることを示す |
| 内側の縁ハイライト | 上端 2px の明かり。厚みのある板の上面に見せる |
| 文明色の深み | 上が明るく下が沈む。フェイス外周は文明色、胴は暗色に文明色を混ぜる |

対象は `.mcard`(外周の枠)/ `.mcard-inner`(胴)/ `.mcard-head`(頭)/ `.mcard-type`
(型の帯)/ `.mcard-foot`(足)/ `.mcard-cost`(コストの宝石)/ `.mcard-backface`(裏面)
/ `.mcard-frame`(盤面タイルの枠)である。
**共有クラス(`.leader-card` / `.minion-row` / `.mana-chip` / `.mana-row`)には触れていない。**

## 2. 中心にある設計判断

### 2-1. ★★光沢の「形」は1箇所にあり、場所ごとに変えるのは強さだけである

頭・胴・足・枠・タイルの5箇所に同じ角度の光を走らせる必要がある。素直に書くと
`linear-gradient(115deg, ...)` が5回現れ、**角度を直したいときに直す場所が5つ**になる。
これは「見た目の正は1箇所」(25 以来の方針)に反する。

そこでカスタムプロパティの**遅延解決**を使った。

```css
.mcard, .mcard-backface, .mcard-frame {
    --mc-sheen: 0.14;                       /* 強さ */
    --mc-gloss: linear-gradient(115deg,     /* 形。--mc-sheen を中に含む */
        rgba(255, 255, 255, 0) 0 26%,
        rgba(255, 255, 255, var(--mc-sheen)) 37%,
        rgba(255, 255, 255, calc(var(--mc-sheen) * 0.3)) 45%,
        rgba(255, 255, 255, 0) 55% 100%);
}
.mcard-inner { --mc-sheen: 0.05; background: var(--mc-gloss), ...; }
.mcard-head  { --mc-sheen: 0.12; background: var(--mc-gloss), ...; }
```

`--mc-gloss` の中の `var(--mc-sheen)` は、**`--mc-gloss` が実際のプロパティへ
代入される要素**の値で解決される。だから `--mc-gloss` は継承させたまま、
`--mc-sheen` だけを子で上書きすれば、同じ角度・同じ形の光が強さだけ変わって走る。

★角度を変えたいときに触るのは1行である。文明色(`--mc`)が1箇所である(25b)のと
同じ形が、光沢にも入ったことになる。

### 2-2. ★★★transform と filter は一切使わない — 32b の申し送りへの回答

32b 6章の申し送りは次のとおりだった。

> ★32b で `.manual-fx-tap` が transform / filter を遷移させる。
> フェイスに transform や filter を使う質感(内側の影など)を足すときは、
> タップの遷移に巻き込まれないか確認すること。

確認した結果、**巻き込まれないように作るのではなく、そもそも使わない**ことにした。
理由は2つあり、2つめのほうが重い。

1. `.manual-fx-tap` は `transition-property: transform, filter` である。
   フェイスがそれらを質感のために持つと、タップのたびに質感まで 160ms かけて
   遷移の対象になる。
2. **★★`.manual-tile-tapped` の `filter: brightness(0.62)` は「置き換え」であって
   「合成」ではない。** 盤面のタイルは `.mcard-frame` そのものなので、基底に
   `filter` を持たせると、**タップしている間だけその質感が消える**。
   さらに悪いことに、減光と基底の filter が混ざるため
   「場のタイルは減光する」という 26/30 の非対称そのものが崩れる。

立体感は `background` と `box-shadow` だけで出している。
**この決めごとは機械で押さえた(4章・項目63)。**

### 2-3. ★★擬似要素も使わない

32b 6章のもう1つの申し送り:

> ★めくりのゴーストは `backface-visibility: hidden` を効かせている。
> フェイスに擬似要素で光沢を足す場合、裏返り中の見え方を1度確認すること。

`::before` で光沢の板を1枚重ねる書き方は一般的だが、めくりのゴーストは
`rotateY` で裏返る要素であり、その中に増やしたレイヤの見え方は
「今は大丈夫」で済ませたくない性質のものである。
**多層 background なら要素は1つのままで、裏返り中も確実に1枚の板として振る舞う。**

設計書が最初から「多層 background」と書いていたのは、おそらくこの理由による。
今回はその指定に素直に従い、**確認すべき事象そのものを作らなかった**。

### 2-4. ★縁のハイライトは box-shadow ではなく background の層で描く

`inset` の `box-shadow` で縁を描くのが最短だが、盤面のタイルには
`.manual-denied`(非公開ゾーンを押したときの明滅・21c 3-5)が付く。
これは `box-shadow` を `none` ↔ 赤枠 でアニメーションするため、
**縁を box-shadow で描くと明滅中だけ縁が消える。**

そこで縁のハイライトは `linear-gradient(180deg, rgba(255,255,255,α) 0, transparent 2px)`
という**背景の層**で描いた。`box-shadow` を使っているのは
`.mcard` と `.mcard-backface` の**外側の落ち影**だけであり、
これらは `.manual-denied` が付く要素ではない(明滅が付くのはゾーンの入れ物である)。

### 2-5. 盤面タイル(`.mcard-frame`)も対象に含めた

設計書3章は対象を「`.mcard-*`」と書いており、`.mcard-frame` はその中にある。
判断が要ったのは「盤面まで変えるか」で、**変えることにした。**

- 25b でパレットを1系統へ統一した目的は、**フェイスとタイルが同じ見た目の系統に
  乗る**ことだった。手札のフェイスだけ艶を持ち、盤面のタイルが平らなままだと、
  その統一が今回の変更でちょうど崩れる。どちらか一方に揃えるより悪い状態である。
- ただし盤面は密で小さい。光沢は手札より弱くした(0.14 → 0.10)。
- 下端に暗い層を1枚足し、タイルが「下から陰が回り込んだ板」に見えるようにした。

★戻す場合は `.mcard-frame` の `background` を 25b の2色グラデーションへ戻すだけでよい
(他の `.mcard-*` とは独立している)。

### 2-6. 胴の光沢は 0.05 まで落としてある

`.mcard-inner` は**読む面**である。26 の3章で「テキストが載って読む面になった」と
書いたとおり、ここに模様を作ると効果テキストの可読性が下がる。
光沢は他の 1/3 以下にし、代わりに文明色の深み(下へ行くほど文明色が濃くなる)で
面としての情報を持たせた。

`.mcard-atk` / `.mcard-hp` には `text-shadow` を1枚敷いた。足の地が文明色で
明るくなったぶんの相殺であり、**色そのものは 25 のまま変えていない**。

## 3. 色とコントラストについて

**★フェイスはコントラストの機械判定の対象外である**(30 の判断、設計書32 3章)。
`backgroundColor` からは背景を辿れず(グラデーションである)、判定できないものを
判定したふりにしないためである。判定の対象セレクタは 32b から変えていない。

そのぶん、**判定できないものは人間が見る**。4章の目視確認がその代わりである。

なお、地が明るくなる方向の変更は次の2箇所に限ってあり、いずれも
最も明るい文明色(光 `#b8952f`)でも 4.5:1 を下回らないことを手計算で確認した。

| 箇所 | 変更 | 最悪ケース(光文明)の比 |
|---|---|---|
| `.mcard-head` の上端 | 文明色 38% → 46% | 約 6.1:1(文字 `#ece8f7`) |
| `.mcard-foot` の下端 | 文明色 22% → 32% | 約 5.5:1(文字 `#f0c869` / `#e88a9a`、text-shadow 込みでさらに有利) |

## 4. 検証

### 4-1. 機械で押さえたのは「綺麗か」ではなく「巻き込まれないか」である(項目63)

質感の良し悪しは機械で測れない。**測れるのは 2-2 の決めごとのほうである。**

> 項目63: `#manual-root` の中の `.mcard` / `.mcard-inner` / `.mcard-head` /
> `.mcard-type` / `.mcard-foot` / `.mcard-cost` / `.mcard-backface` / `.mcard-frame` は、
> 静止時に computed `transform` と `filter` がいずれも `none` であること。

★盤面が空だと無条件に通るので、**実際にどのセレクタを見たか**も返して
6種類以上あることを条件にしてある(「常に通る飾りの検証」にしない)。

### 4-2. ★わざと壊して落ちることを確かめた(納品前に実施)

`.mcard-frame { filter: saturate(1.2); }` と
`.mcard-inner { transform: translateZ(0); }` を一時的に足して実行した。

| 落ちた項目 | 意味 |
|---|---|
| **63** | 期待どおり(2箇所とも検出。どのセレクタ・どの値かまで報告する) |
| **54**(32b) | ★★「場のタイルは filter(減光)だけで回らない」が落ちた |
| **26 の既存項目** | ★★「場のタイルのタップは回転ではなく減光+バッジのまま」が落ちた |

★**54 と 26 が一緒に落ちたことが、2-2 の第2の理由の実物である。**
基底に `filter` を置くと `.manual-tile-tapped` の `brightness()` が置き換えとして
振る舞い、タップの減光が検出できなくなる。「質感を足しただけ」のつもりの1行が、
26 から積み上げてきたタップ表現の非対称を静かに壊す——それが実際に起きた。

### 4-3. 目視確認(★このバッチでは必須。設計書32 3章)

`verify/faceshot.js` を新設した。全文明(7)× 全 variant(large / full / mini / micro)
+ 裏面 + 盤面タイルの枠を、**実ページと同じ黒背景 `#212529` の上に**1枚に並べて撮る。

```bash
PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers OUT=/tmp/faces.png node verify/faceshot.js
```

★見た目の正は `cardFace()` / `cardBackFace()` そのものである。サンプラは
それらを呼ぶだけで、**ゴースト専用の見た目を作らない**という 32a 2-3 の規約と
同じ考え方に立っている(サンプラ専用の見た目を作らない)。

確認したのは次の点である。

1. 全7文明で光沢の角度・強さが揃っており、どの文明色でも白飛びしない。
2. large / full の効果テキストが胴の光沢に埋もれない。
3. micro(46×64)でも縁と頭が潰れず、カードの境界が黒背景から分離する。
4. **タップの遷移の途中**(80ms)で、回転するマナの光沢が板と一緒に回り、
   隣のマナへ食い込まない(`applyManaOverlap` の幅確保は 30 のまま無変更)。
5. **めくりの前後**で厚み(落ち影)が変わらない。
6. 拡大パネル・パイル面・帯・相手上段のいずれでもレイアウトが1pxも動かない。

## 5. マスターへの依頼・確認事項

1. **★★`mvn test` を手元で実行してほしい。**
   サンドボックスから Maven Central へ到達できないためこちらでは走らせられない。
   ただし**本バッチは Java も JavaScript も変更していない**(CSS・テンプレートの版数・
   検証スクリプトのみ)。落ちる要素は無い見込みである。

2. **質感の強さ**を実機で見てほしい。強さは `--mc-sheen` の1つの数値である。

   | 場所 | 現在値 |
   |---|---|
   | `.mcard`(外周の枠) | 0.14 |
   | `.mcard-head`(頭) | 0.12 |
   | `.mcard-frame`(盤面タイル) | 0.10 |
   | `.mcard-foot`(足) | 0.07 |
   | `.mcard-backface`(裏面) | 0.07 |
   | `.mcard-inner`(胴・読む面) | 0.05 |

   全体を一段落とすなら、共通定義の 0.14 を下げたうえで各値を比例で下げればよい。
   角度(115度)を変える場合は共通定義の1行だけである。

3. **盤面タイル(`.mcard-frame`)まで質感を通したこと**の可否(2-5)。
   フェイスとタイルを同じ系統に保つ判断だが、盤面が賑やかに見えるようなら
   ここだけ 25b の2色グラデーションへ戻せる(独立している)。

4. **拡大パネルの落ち影**は入れていない。フェイス自身の `box-shadow`(1px)だけである。
   拡大時にもっと浮かせたい場合は `#zoom-panel .mcard` に1行足す形になる。
