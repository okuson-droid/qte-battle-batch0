## 1. ★★★裁定353 —— 宣言の器

### 1-1. 何が起きていたか

★<b>いちばん効いた症状</b>:

> **特殊召喚を持つカードをドラッグして場に落とし、[キャンセル] を押すと、通常プレイで出る。**
> つまり<b>ドラッグを取り消す手段が1つも無かった</b>。

72 の `askConfirm` は<b>実行する側しかない器</b>である(裁定54)——
「使う分岐は片方しかない」という前提で書かれており、宣言には載らない。

★★**[キャンセル] というボタンが「通常プレイする」を意味するのは、
裁定55(ボタンには動詞を書く)の真逆である。**

### 1-2. 形 —— 出口を3つにした

```
[A の姿で使う] / [B の姿で使う] / [やめる](× ・Esc も同じ)
```

★**やめても失うものは何も無い** —— 宣言の時点でサーバへは1バイトも送っていない。
<b>取り返しがつくどころか、何も起きていない</b>。

★★**初期フォーカスは [やめる]** である(裁定52 の筋)——
A も B も<b>どちらも送る側</b>なので、Enter を押しただけで片方が選ばれてはいけない。

### 1-3. ★問いの本文から「OK = / キャンセル =」の尾を落とした

77 まで `soulPrompt` はこう終わっていた:

```
OK = スペルとして使う(コスト1) / キャンセル = ミニオンとして出す
```

★あれは素の `confirm()` が**ボタンの文言を決められない**ために、
何が起きるかを<b>問いの本文へ全部書くしかなかった</b>名残である(36 が捨てた理由2)。
★★いまは**ボタンに動詞が載る**ので、本文はカードの話だけをすればよい。

### 1-4. ★入口で言い方を分ける

| 入口 | A のボタン | 理由 |
|---|---|---|
| 手札の賢魂 | `スペルとして使う(コスト1 → 実効1)` | ★コスト軽減を受ける |
| **禁忌の賢魂** | `スペルとして使う(マナ1枚)` | ★★**禁忌はコスト軽減を受けない**(枚数で払う) |

★<b>入口で言い方が違うことに意味がある</b> —— 壊し検証の軸10 がここを見張る。

### 1-5. ★問いは連鎖する

賢魂 → (選ばなければ)特殊召喚 / 強化、という<b>2段の問い</b>になりうる。
★235枚に「賢魂かつ特殊召喚」も「賢魂かつ強化」も**今は1枚も無い**が、
★★<b>無いことに寄りかからない</b> —— 連鎖する形で書いてある(74 の教訓・陰)。

### 1-6. ★落とし先の検査を宣言より前へ出した

77 まで、進化を素材でない場所へ落とすと
**先に特殊召喚を問われてから**「素材の上に落としてください」で捨てられていた。

★**答えが捨てられる問いを出さない。**
★★<b>禁忌の道(77)は既にこの順である</b> —— 入口で手触りを揃えた(裁定352 の筋)。

## 2. ★★★裁定354 —— モーダルの層とフォーカストラップ

### 2-1. 何が無かったか

- ★Esc は**優先順を5段ベタ書きした if の列**だった。
- ★★★**フォーカストラップは1つも無かった**(裁定50 が通常モードだけ未実施だった)。
- ★`askConfirm` は `.focus()` を直に呼ぶだけで、
  <b>閉じたあとの戻り先を誰も決めていなかった</b>(裁定50 の残り半分)。

### 2-2. 形 —— 36 を写した

`FOCUSABLE_SELECTOR` / `modalStack` / `isShown` / `focusablesIn` /
`applyInitialFocus` / `restoreFocus` / `pushModalLayer` / `popModalLayer` /
`topModalLayer` と、**Esc と Tab を受ける1つの keydown**、**focusin の網**。

★78 が足したのは `syncModalLayer(id, shown, options)` の1つだけである ——
<b>開閉と層への出入りを1行に載せる</b>ための糖衣であり、
「開いたのに積まれていない」が静かに起きないようにする。

### 2-3. ★★★閉じ込めないが、層には積むもの

| 要素 | 閉じ込めない理由 | それでも積む理由 |
|---|---|---|
| `#auto-zoom` | 焦点可能な要素が**1つも無い** | Esc を層で受けるため |
| `#log-panel` | **配信のたびに中身を作り直す**(36 が帯・全面表示を外したのと同じ) | 同上 |
| `#auto-offline` | ★★**71 の判断そのもの** —— 操作を止めているのは `send()` のガードであって覆いではなく、**[盤面を確認する] で畳める**。閉じ込めると矛盾する | ★★★**z-index 1970 は確認(1965)より上**である。積まないと<b>見えていない確認モーダルにフォーカスが閉じ込められる</b> |

> ★★★**重ね順の真実と、層の真実を一致させる**(裁定56)。

### 2-4. ★出口の有無という1つの事実から、× と Esc の2つが同時に決まる

`#deck-gate` と `#seat-gate`(JOIN・部屋消失)には [閉じる] が無い ——
だから **Esc も効かない**(裁定34)。
★★逆に `#info-modal` は [閉じる] を持っているので、**効くのが正である**(裁定35 の一般化)。
77 まで効いていなかったのは、単に誰も繋いでいなかっただけである。

### 2-5. ★★配信のたびに積み直される層が2つある

`renderDeckGate` と `updateOfflineLock` は<b>配信のたびに呼ばれる</b>。
★`pushModalLayer` の「二重に積まない」「**フォーカスが中にあるうちは触らない**」が
<b>通常モードでは日常的に効く</b> ——
当て直すと<b>デッキファイルを選んでいる最中に先頭のボタンへ飛ぶ</b>。

## 3. ★★★78 が新しく開けた穴と、その手当て

裁定53 の理由3 は「素の `confirm()` は**JavaScript を止める**」だった。78 はそれを直した。

★**ところが、直した結果として逆の穴が開く** ——
<b>問うている間も配信は届き、盤面が動きうる</b>。

★★77 までのコールバック(投了・席・退室・再戦)は**どれも位置を持たなかった**ので、
この問題に当たらなかった ——
★★★**78 が初めて「手札の何枚目」を非同期の向こうへ運ぶ。**

```js
function stillThere(zone, index, cardId) {
    const list = latestView && latestView.you ? latestView.you[zone] : null;
    return !!(list && list[index] && list[index].cardId === cardId);
}
```

★答えが返った時点で引き直し、一致しなければ**何もしない**。
★★<b>違うカードを使ってしまうより、何も起きないほうが桁違いにましである</b>
(設計判断49 の「畳まない」と同じ筋)。

> ★★★**次に「非同期の向こうへ位置を運ぶ」ものを作るときは、必ず引き直すこと。**
