前提: `batch16-manual-mode-design-v2_4.md`(唯一の正)+ `notes/batch19a-design-notes.md`。
本書が設計書 4章(画面)の該当箇所を上書きする。

v1 → v2 の変更: モックアップ確認後の追加指摘7件(4章の8〜14)を反映した。

18b が7枠で実装したのが誤りであり、UIを6枠に訂正する(2-9)。
右列をさらに縮小(280→224px)、リーダー行を
[ウェポン][リーダー][禁忌][山札][公開][墓地][消滅] の並びに再編し、

## ⚡ 結論チートシート

- **3列構成 → 2列構成。** 左のゾーンバー列(110px)を廃止し、中央列を 840px に拡幅。
  **ミニオン枠が1行に収まる**(現状は折り返しが発生していた)。
- **★場のミニオン上限は6体**(発注者指摘)。18b が7枠で実装したのは誤り。
  UIの既定表示を6枠に訂正する。通常モード(Java)は元から6で正しい(2-9)。
- **右列(ログ・拡大画像)は 350px → 224px**(発注者指摘2回: 8割 × さらに8割 = 6.4割)。
  拡大画像は 204×286 になる。
- **リーダー行は左から [ウェポン][リーダー][禁忌][山札][公開][墓地][消滅]。**
  リーダーは 110→90px に縮め、山札はパイルと同じ 90×120px に拡大する(発注者指摘)。
- **マナはリーダー行の直下の独立行。** 表/裏の2ストリップを横に並べ、ストリップ全体を
  ドロップ領域にする。**マナカードは 64×88px に拡大し、カード名を表示する。**
  1行に収まらない枚数は少し重ねて表示する。
- **山札・禁忌のパイルは一番上のカード名を表示しない**(非公開ゾーンの秘匿。発注者指摘)。
  墓地・消滅・公開は公開ゾーンなので表示を維持する。
- **裏向きカードの拡大表示は表面画像 + 「裏向き」バッジ。** フェイズ1は全公開であり、
  裏面画像を出しても確認できない(発注者指摘)。
- **★指摘「帯からドラッグできない」は 18c のバグ。** 帯のバックドロップ(全画面・
  z-index 1040)が盤面へのドロップイベントを遮断していた。ドラッグ中だけ
  pointer-events を切って直す。
- **ヘッダに「?」ボタンを追加し、操作説明モーダルを表示する。**
- **★ゲームの正式名称は「クイン・タブーエレメント」。** 「エレメンタル」は誤記。
  リポジトリ内5箇所を 19b で修正する(2-8)。
- 変更ファイル: `manual-battle.html` / `manual-battle.js`(v=3→v=4)/
  `battle.css`(v=12→v=13)+ 名称修正の `lobby.html` / `cards.html` /

## 0. 指摘と原因の対応表(初回レビュー分)

| # | 指摘 | コード上の原因 |
|---|---|---|
| 1 | 左のゾーンパイルが縦に短すぎる。どのゾーンか一目で分からない。山札はリーダーの近くに置くべき | `.zone-pile` はヘッダ1行+カード名1行の小箱(高さ約50px)で、5個縦に並べても列の高さの半分も使わない。ラベルは小さな灰色文字のみ |
| 2 | ミニオン7枠が1行に収まらずスクロールが必要。ウェポンの1行がもったいない | 場タイルは 110px 固定・gap 8px で、7枠に **818px** 必要。中央列は **700px** しかなく `flex-wrap: wrap` で2行に折り返す。B席も同じ。ウェポンは `minion-row`(min-height 110px)を丸ごと1行占有 |
| 3 | 帯(ゾーンの一覧表示)からドラッグでゾーン間移動ができない | **18c のバグ。** `.manual-band-backdrop` が `position: fixed; inset: 0; z-index: 1040` で全画面を覆っており、盤面のドロップ対象は帯を開いている間 dragover/drop を一切受け取れない。帯のカードの `draggable` と `onDragStart` 自体は実装されていたが、着地点が存在しなかった |
| 4 | 操作方法の解説テキストをクリックで表示したい | 該当機能が存在しない |
| 5 | マナの表/裏などのドロップエリアが小さい | `.zone-drop-mini` は font-size 9px・padding 2px の点線帯(高さ約16px)。マナチップ自体も 22×30px |

★指摘3について: 18c の design-notes は「帯から盤面へ直接ドラッグできる」と記載して
納品したが、実際にはバックドロップの遮断により一度も機能していなかった。
「実装した」という記述と動作の実態が食い違った事例として、既知の落とし穴に追記する。

コンテナ幅は 1200px を維持する。中央 840px + 右 224px の2列にする。

```
│ B席: [Bリーダー] [山40|墓0|消0|禁8|公0] ← 小型バー      │ ログ          │
│ Bミニオン: [ 1 ][ 2 ][ 3 ][ 4 ][ 5 ][ 6 ]             │              │
│ Aミニオン: [ 1 ][ 2 ][ 3 ][ 4 ][ 5 ][ 6 ]             │              │

│       110px    90px   90×120のカード型パイル ×5        │ 204×286      │
│ マナ MP3: [表 ▢▢▢▢▢▢…重ね] [裏 ▢▢…]  ← 2ストリップ  │              │
│ 手札: ▢▢▢▢▢▢▢▢ …                                   │              │
└─────────────────────────────────────────────┴──────────────┘
```

**幅の検算**:
- ミニオン行(6枠): 110×6 + gap 8×5 = 700 + パディング16 = 716 ≦ 840。
- リーダー行: ウェポン110 + リーダー90 + パイル90×5 + gap 8×6 = 698 + 16 = 714 ≦ 840。
  ミニオン行(716)とほぼ同幅で揃う。
- 全体: 840 + gap 8 + 224 = **1072px** ≦ 1200px。

**高さの見積り**: ヘッダ類 約90 + B席行 84 + Bミニオン 118 + Aミニオン 118 +
リーダー行 約136 + マナ行 約104 + 手札 約140 = **約790px**。
1080p のブラウザ表示領域(約940px)にスクロール無しで収まる。

## 2. 各要素の設計

### 2-1. リーダー行 — 並び順とサイズ(発注者指定)

左から **[ウェポン][リーダー][禁忌][山札][公開][墓地][消滅]** の順で固定する。

| 要素 | サイズ | 備考 |
|---|---|---|
| ウェポン枠 | 110×120px | 場タイルと同幅。未装備は点線の空き枠(ドロップ対象)。複数装備は右に伸びる |
| リーダー | 90×120px | 110→90 に縮小(発注者指摘)。LP・タップ表現は現状踏襲 |
| 禁忌・山札・公開・墓地・消滅 | 各 90×120px | カード型パイル(2-2) |

### 2-2. カード型パイル(禁忌・山札・公開・墓地・消滅)

```
┌────────┐         ┌────────┐
│ 墓地       │         │ 山札       │
│    5       │         │   34       │
│ 落石の罠    │         │ [シャッフル] │
└────────┘         │ [上へ][下へ] │
 公開ゾーン            └────────┘
 (一番上の名前あり)      非公開ゾーン(名前なし)
```

- ゾーン名 太字13px / 枚数 太字20px。
- **★一番上のカード名を出すのは公開ゾーン(墓地・消滅・公開)のみ。**
  **山札・禁忌は枚数だけを表示する**(発注者指摘: 非公開情報が見えてしまっていた)。
  フェイズ1は全公開だが、対戦の練習として盤面の見た目は本来の公開範囲に寄せる。
  中身の確認は従来どおり帯・全面表示で行えばよい。
- 操作は 18c と同じ: 左クリック=帯を開く(山札は1枚ドロー)/ 右クリック=最上段の拡大
  (山札は全面表示)。山札パイルの下部にシャッフルボタンと「上へ」「下へ」ドロップを収める。
- パイル全体がドロップ対象(面積は現状の約4倍)。

### 2-3. マナ行 — リーダー行の直下(発注者指定)

```
マナ MP 3
┌ 表 ─────────────────────────┐┌ 裏 ──────────┐
│ [名前][名前][名前][名前]…(重ね)   ││ [名前][名前]     │
└─────────────────────────┘└──────────┘
```

- リーダー行の下の独立行。**表ストリップ(約6割幅)と裏ストリップ(約4割幅)を横に並べる。**
- **マナカードは 64×88px のミニタイルに拡大し、カード名を表示する**(発注者指摘)。
  文明色の背景 + 名前(縦書きは使わず、小さめフォントで折り返し)。
  タップ済みは横倒し(rotate 90deg)で現状踏襲。
- **ストリップ幅に収まらない枚数は重ねて表示する**(発注者指摘)。実装は
  「はみ出す場合のみ負のマージンを計算して均等に重ねる」方式。最大15枚が
  表ストリップ(約470px)に収まるまで重なりを深くする(1枚あたり最小約28px露出)。
- ストリップ全体がドロップ領域(表ストリップ=表向きで置く / 裏=裏向きで置く)。
- ストリップ間のドラッグ = 同一ゾーン内移動 + faceDown 変更(サーバ変更不要)。
- 個々のカードの Shift+クリック(表裏)・クリック(タップ)等の既存操作は維持する。

### 2-4. 裏向きカードの拡大表示(発注者指摘)

**拡大表示(右下パネル・固定表示とも)は常に表面画像を表示し、「裏向き」バッジを重ねる。**

現状は裏向きカードの拡大に裏面画像を出しており、確認の用をなしていなかった。
フェイズ1は全公開であり、持ち主が自分の裏向きマナ・裏向き山札上のカードを確認できる
べきである。帯の中の裏向き表示(「(裏向き)」の無地タイル)は現状を維持し、
拡大したときだけ表面が見える、という関係にする。

★フェイズ2(対戦モード)では、そもそもサーバが相手の非公開カードの imageId を
ビューに載せない設計(設計書11-3)であるため、この変更が情報漏えいの経路になることは無い。

### 2-5. 帯からのドラッグ修正(バグ修正)

ドラッグ開始時にバックドロップの遮断を解除する。

1. 帯カードの `dragstart` で `<body>` に `manual-drag-active` クラスを付与し、
   `dragend` で外す。
2. CSS に次を追加する。

```css
body.manual-drag-active .manual-band-backdrop,
body.manual-drag-active .manual-band {
    pointer-events: none;
}
```

帯自身も透過させるのは、帯の背後に隠れている盤面上部(B席行)へも落とせるようにする
ためである。ドロップが成功するとサーバが再配信し、`refreshOverlay()` が帯を描き直す
ため、追加の後始末は不要である。

### 2-6. 操作説明モーダル

ヘッダ右端の「?」ボタンで開く。内容は静的 HTML として `manual-battle.html` に直接書く。

| 分類 | 内容 |
|---|---|
| カード共通 | 左クリック=拡大(タップ対象はタップ) / 右クリック=拡大固定 / Shift+クリック=表裏 / Ctrl(Cmd)+クリック=複数選択 |
| ドラッグ | ゾーン間移動。場の既存タイルに重ねる=進化。複数選択中は選択分をまとめて移動。帯・全面表示からも盤面へ直接ドラッグできる |
| 山札 | 左クリック=1枚ドロー / 右クリック=全面表示(並べ替え・検索) / シャッフル / 上へ・下へ |
| パイル | 左クリック=帯を開く / 右クリック=最上段の拡大(山札・禁忌は枚数のみ表示) |
| マナ | 表/裏ストリップへのドロップで向きが決まる。ストリップ間ドラッグで表裏変更。MPはアンタップ枚数の自動計算 |
| 数値・札 | タイルの数値クリック=編集 / +ボタン=札の付け外し |
| ヘッダ | リセットして引き直す(履歴は消える) / ログ書き出し / 退室 / Undo・Redo(深さ200) |

### 2-7. B席と右列

- B席行は [Bリーダー] + [小型ゾーンバー] の1行、Bミニオン行を独立(折り返し解消)。
- 小型ゾーンバーはクリック無効の飾りのまま(18c 0-2 Q1 の裁定維持)。
  ドロップ受けの面積だけ 32×24 → 44×32px に拡大。
- **右列は 224px**(ログ + 拡大画像 204×286)。宣言ボタン(勝利/敗北/引分/投了)は
  現状どおり拡大画像の上に置くが、幅に合わせて縮む。

### 2-9. ミニオン枠数の訂正 — ★重要(v2.1)

**場のミニオンゾーンの上限は6体である。** 7体は誤り(発注者指摘・2026-08-04 確定)。

調査結果:

| 箇所 | 状態 |
|---|---|
| 通常モード `PlayerState.DEFAULT_MINION_ZONE_LIMIT` | **6 で元から正しい**(修正不要)。大地の巨頭(QTE-L011)のみ Ver.0.4 の常在能力で8体に引き上げる動的上限も実装済み |
| 手動モード `manual-battle.js` 323行・352行 | `renderStackRow(fieldRow, seat, 'FIELD', 7)` — **18b の実装誤り。6 に訂正する** |
| 本設計書 v2 以前・18b/18c design-notes の「7枠」記載 | 本書 v2.1 で訂正。過去の design-notes は履歴として残す |

手動モードにおける「6」は**既定の空き枠表示の数**であり、上限の強制ではない
(設計書5-1: 判断は実装しない)。7体目以降を置くことは引き続き可能で、その場合は
行が折り返して表示される。大地の巨頭による8体運用もこの折り返しで表現できる。

★プロジェクトナレッジ側の設計文書に「7枠」「7体」の記載が残っていれば、
発注者側での修正を依頼する。
