# Batch 32b 設計解説 — 状態系(タップ・めくり)+ 節目系(ターン・進化)

設計書 `notes/batch32-effects-design.md` 5章の分割に従い、32系の2本目を実装した。
基盤(fx層・差分検出・捕捉・スポーン・上限・抑制)は 32a のものをそのまま使っている。
**Java の変更はゼロである。**

| ファイル | 内容 |
|---|---|
| `src/main/resources/static/js/manual-battle.js` | ★本体。`diffViews` に語彙4つ、8-2章に状態系・節目系の演出を追加 |
| `src/main/resources/static/css/battle.css` | タップ遷移・めくり・沈み込み・ターン帯(版数 v=30) |
| `src/main/resources/templates/manual-battle.html` | 版数(js v=23 / css v=30) |

検証: `300/300 passed`(32a時点の 288 + 12)。機械チェック一式もすべて通過。
`javac -proc:none` の構文走査も通過(Java は1行も触っていない)。

## 1. 何を作ったか

| 差分の語彙 | 検出 | 演出 |
|---|---|---|
| `tapChanged` | 同一 instanceId の `tapped` が変化 | マナは回転・場のタイルは減光を **160ms かけて** |
| `flipped` | 同一 instanceId の `faceDown` が変化 | 2段階のめくり(110ms × 2) |
| `stackGrew` | 同一 instanceId の `stackSize` が増加 | 到着タイルの沈み込みパルス(180ms)+ `+n` バッジの跳ね |
| `turnAdvanced` | `turnNumber` が **増加** | 盤面中央に「ターン n」の帯(900ms) |

いずれも 32a と同じく **ビューの差分だけ**を材料にしており、サーバは1行も変えていない。

## 2. 中心にある設計判断

### 2-1. ★★状態系は「居場所が変わっていないカード」だけを見る

`diffViews` の突合ループで、移動が見つかった時点で `continue` している。
同じ1枚に「飛ぶゴースト」と「その場の遷移」を重ねると、何が起きたのかがかえって読めない。

語彙の切り分けとしても素直である。

- **移動系** = どこからどこへ行ったか
- **状態系** = その場で何が変わったか

### 2-2. ★★★タップ表現の非対称は「要素が持っているクラス」から決める

26 / 30 で確定した非対称を維持する。

```
自席のマナ(.mana-tile)         → 回転 rotate(90deg)
相手マナの簡略タイル             → 減光 .manual-opp-tapped
場のタイル・リーダー             → 減光 + バッジ .manual-tile-tapped
```

ここで「マナなら回転」と JS に書き直すと、**表現の正が2箇所になる**。
どちらの表現かは `fxTapStateClass` が**要素が既に持っているクラス**から引く。
CSS 側 `.manual-fx-tap` が持つのは**遷移だけ**であり、
何が動くか(transform か filter か)は状態クラスがそのまま決める。

★この非対称は**機械で**押さえた(検証項目54)。場のタイルに `transform` の遷移が
走った瞬間に落ちる。どちらかに揃えてしまう改修は、二度と黙って通らない。

### 2-3. ★★★遷移のクラスは「最終状態」と一緒に当てる — 開発中に踏んだ罠

**これが 32b で最も時間を使った箇所であり、最も再発しやすい形である。**

`renderAll` は毎回DOMを作り直すので、作られた時点で最終状態のクラスが付いている。
CSS の transition は初期値には効かないため、32a まではタップが一瞬で切り替わっていた。
直し方は設計書 2-4 の「次フレーム切替」——**いったん旧状態へ戻し、確定させてから
最終状態へ戻す**である。ここまでは設計どおりだった。

最初の実装は、旧状態へ戻すときに遷移クラス(`.manual-fx-tap`)も一緒に当てていた。
すると次のことが起きる。

```
確定の瞬間:  最終状態 → 旧状態 の遷移が走り出す   (向きが逆!)
その直後  :  旧状態 → 最終状態 へ戻す
```

CSS Transitions の規定では、**走行中の遷移の現在値が新しい最終値と等しいとき、
その遷移は取り消され、新しい遷移は始まらない**。開始直後なので現在値は最終状態そのもの
であり、条件にぴたりと当てはまる。

結果、**クラスは全部正しく付いているのに何も動かない**。DOM を覗いても
`manual-fx-tap` も `tapped` も付いており、computed style も正しい。
何も間違っているように見えないのに、演出だけが無い——**音を立てない壊れ方**である。

正しい順序は次のとおり。

```js
// build 相: 旧状態へ戻す。★遷移クラスはまだ付けない(duration 0 のまま値を戻す)
el.classList.toggle(stateClass, !fx.tapped);
// ── ここで1回だけ確定させる ──
// play 相: 遷移クラスと最終状態を同時に当てる
el.classList.add('manual-fx-tap');
el.classList.toggle(stateClass, fx.tapped);
```

★この罠は「クラスが付いたか」を見る検証では**絶対に捕まらない**。
だから検証は `transitionstart` を捕まえる形にした(4章)。

### 2-4. ★強制同期レイアウトの相手を fx層からルート要素へ変えた

32a は `void layer.offsetWidth` で開始状態を確定させていた。32a が動かすのは
ゴースト(fx層の中)だけだったので、それで筋が通っていた。

32b の状態系は **盤面の実要素**(`#manual-root` の中)に当たる。
実測では fx層を読んでも文書全体が確定するが、それは
「強制同期レイアウトが文書全体を確定させる」という実装上の性質に寄りかかった書き方で、
**なぜそれで足りるのかがコードから読めない**。確定させたいものを含む要素を読むべきである。
`document.documentElement.offsetHeight` はページ全体のレイアウトを要求する。

★**強制同期レイアウトが1回だけであることは変わっていない**(29 の相分離)。

### 2-5. めくりは2段階。実タイルは `opacity` で隠す

```
前半 110ms: 旧い面のゴーストが rotateY(0deg → 90deg) で立つ
後半 110ms: 中身を新しい面へ差し替え、rotateY(-90deg → 0deg) で倒れる
```

ゴーストが真横(90deg)を向いた瞬間に下から新しい面が覗くと、めくりに見えない。
そこで実タイルを演出のあいだ透明にする。

- ★**`visibility` ではなく `opacity`** である。`visibility: hidden` は当たり判定まで
  消すので、演出中の 220ms だけカードが押せなくなる。
- ★**終了イベントを購読しない**(`event: null`)。前半の `transitionend` で
  閉じてしまうためである。タイマーだけで閉じる。
- ★**クラスを剥がすのは `onStop` の仕事**である。途中で次の配信が来て要素が
  作り直されても、剥がす相手が**捨てられた要素**になるだけで盤面は壊れない。

★情報漏れは構造的に起きない。前半は旧ビューのカード、後半は新ビューのカードを
そのまま `fxGhostBody` に渡すだけであり、裏向きなら `cardBackFace()`
(imageId を持たない)に落ちる。

★**「めくったカードが二度と見えない」は演出の失敗ではなく盤面の欠落である。**
27 の「画面のどこからも触れない = 消失」と同じ重さの事故なので、
後始末が効いていることを独立した検証項目にした(項目55b)。

### 2-6. `fxRegister` を位置引数からオプションへ

32b で「終わったときに元へ戻す処理」(`onStop`)が要るようになった。
`keep` / `endEvent` に続けて3つ目の位置引数を並べると呼び出し側が読めなくなるため、
オプションにまとめた。あわせて2つ直してある。

- **終了イベントは子要素からも上がってくる**(沈み込みのバッジなど)。
  自分自身のぶんでなければ終了と見なさないようにした。
- 32a は `keep` のとき `fxStop` の中で `manual-fx-enter` を名指しで剥がしていた。
  出現の都合が後始末の共通処理に漏れていたので、`onStop` へ移した。

### 2-7. ターンの合図だけは「増加したとき」に限る

Undo で移動やLPが逆再生されるのは**抑制しない**(32a・設計書 1-2)。
実際に起きた状態変化の正確な描画だからである。

ターンの帯だけが例外なのは、あれが**描画ではなく宣言**だからである。
巻き戻して「ターン 2」と宣言するのは、事実の描画ではなく嘘になる。

★検証項目58は、巻き戻しで帯が出ないことに加えて
**同じ配信の他の演出(LPポップ)は出ること**まで見ている。
「演出そのものが止まっている」で通ってしまう検証にしないためである。

### 2-8. ターンの帯を上限の特例にはしていない

「すべてアンタップ」のような一括操作は差分が8件を超え、32a の規定により
**演出が丸ごと出ない**。ターンの帯だけ特例にすることも考えたが、やめた。

- サーバの `setTurn` はターン番号しか変えない。ターン送りと一括アンタップは別の1手であり、
  帯が上限に巻き込まれる経路が現行のカードプール・操作系に存在しない。
- リセットでは `turnNumber` は 1 へ**減る**ので、そもそも帯は出ない。
- 開始シーケンス中は `start.locking` で全体が抑制される。

**要らない特例を作らない。** 必要になった時点で足すほうが安い。

### 2-9. 沈み込みは `animation`、タップは `transition`

32a の出現フェードと同じ理由である。**実要素に当てる演出は `animation` で書く。**
`transition` で書くと「盤面のカード全部に `transition-property` を生やす」ことになり、
マナのタップ回転(transform)を巻き込む(32a 2-9)。

タップだけが `transition` なのは、**走っている要素にだけクラスを付けて、
終わったら必ず剥がす**形にしてあるからである(`.manual-fx-tap`)。
盤面のカード全部に生えているわけではない。

★`prefers-reduced-motion` の停止は、実要素へ当てる演出を**1つずつ**無効にした。
fx層を `display: none` にするだけでは、盤面の中で走る演出は止まらない。

## 4. 検証(12項目を追加。300/300)

### ★★状態系は「クラスが付いた」を見ても検証したことにならない

状態系はゴーストを作らない。実要素の上で transition / animation が走るだけである。
クラスの有無を見るだけでは、2-3 で踏んだ壊れ方——**クラスは全部正しく付いているのに
何も動かない**——が素通りする。

そこで `transitionstart` を捕まえることにした。
これは**ブラウザが遷移を開始したという事実そのもの**であり、
どのプロパティが動いたかまで分かる。
おかげでタップの非対称(項目54)も同じ道具で機械判定できた。

| # | 項目 | 何を守るか |
|---|---|---|
| 53 | 自席マナのタップは `transform` の遷移が**実際に走る** | 2-3 の罠 |
| 54 | **場のタイルは `filter` だけで回らない** | ★★非対称の維持(26/30) |
| 54b | 場のタップはバッジも出す | 減光+バッジ の対 |
| 55 | めくりは前半が旧い面・後半が新しい面 | 2段階・情報漏れ |
| 55b | **めくりが終わると実タイルの透明化は必ず戻る** | 盤面の欠落(2-5) |
| 56 | 進化の増加で沈み込み、ゴーストは作らない | 2-7(設計書) |
| 57 | `turnNumber` 増加で帯が出る | 節目系 |
| 58 | **巻き戻しでは帯を出さない(が LPポップは出る)** | 2-7 |
| 59 | 帯の文字も黒背景で 4.5:1 以上 | 判定の網から漏らさない |
| 60 | ★`fxEnabled` を切ると項目53が検出できなくなる | 自己確認(31 の手順) |
| 61 | ★`tapDetected` は「記録が空」「別プロパティ」「別カード」を認めない | 判定の中身が飾りでないこと |
| 62 | `prefers-reduced-motion` では状態系・節目系も出ない | 演出を切る経路 |

★項目53 と項目60 は**同じシナリオ関数・同じ判定関数**を通る(32a と同じ形)。
別々に書くと「片方だけ直して両方通る」が起きる。

### ★わざと壊して落ちることを確かめた(納品前に実施)

| 壊し方 | 落ちた項目 |
|---|---|
| 遷移クラスを旧状態と一緒に当てる(2-3 の罠を再現) | 53・54 |
| 場のタイルも回転させる(非対称を壊す) | 54 と 26 の既存項目 |
| ターン合図を増加以外でも出す | 58 |
| めくりの後始末(`onStop`)を消す | 55b |
| `fxEnabled` を切る | 60(=落ちることが期待値) |

★このとき、**待てなかったことを例外ではなく FAIL として報告する**ようにも直した。
`waitForFunction` が投げると検証スクリプトごと死に、
「壊したら落ちる」を確かめようとした結果が読めなくなる(1度踏んだ)。

### 目視確認

黒背景のハーネスで、タップ遷移の途中・ターン帯の表示中・演出終了後の3点で
スクリーンショットを撮り、レイアウトが崩れないこと(回転したマナが隣に食い込まない・
帯が盤面の高さを消費しない)を確認した。

## 5. マスターへの依頼・確認事項

1. **★★ターンを進める操作がクライアントに無い。** 20b でターン/フェイズUIを
   表示ごと削除したため、`turn` を送る入口が `manual-battle.js` に存在しない
   (送信できる操作の一覧に `turn` / `phase` が無い)。サーバの `setTurn` は生きている。
   したがって**ターンの合図は、現状の操作系では実際の対戦でぜったいに出ない**。
   検出と演出は設計書どおり入れてあるので、入口ができた日に何もしなくても動く。
   - (a) このままにする(将来ターンUIを戻したときに効く)
   - (b) ヘッダに「ターン +1」の小さなボタンを1つ足す(帯と違い**常設の行は増やさない**)
   - (c) 32c でまとめて判断する

2. **演出の速さ**を実機で見てほしい。タップ 160ms / めくり 110ms×2 /
   沈み込み 180ms / ターン帯 900ms(表示 520ms + フェード 380ms)。
   定数は `manual-battle.js` の1箇所である。

3. **ターン帯の位置**はセンターライン(盤面の縦中央)の中央に出している。
   設計書は「中央上」だが、上に出すと相手の場に重なる時間が長くなるため中央にした。
   文字は 20px。位置・大きさは変えられる。

4. **場のタップはバッジが遷移せず即座に出る**(減光だけが 160ms かけて変わる)。
   バッジもフェードさせるべきか。今回は「バッジは状態の表示であって演出ではない」と
   考えて即時にしてある。

## 6. 32c への申し送り

- 残るのは **カードフェイスの質感**(css v=31・js 変更なし想定)。
  対象は `.mcard-*`(battle.css 末尾・手動モード専用)であり、
  共有クラス(`.leader-card` / `.minion-row` 等)には触らない。
- ★フェイスはグラデーションの上に載るためコントラストの機械判定の対象外である。
  そのぶん**スクリーンショットの目視確認を納品前チェックに必ず含める**
  (設計書3章。判定できないものは人間が見る)。
- ★32b で `.manual-fx-tap` が transform / filter を遷移させる。
  フェイスに transform や filter を使う質感(内側の影など)を足すときは、
  タップの遷移に巻き込まれないか確認すること。
- ★めくりのゴーストは `backface-visibility: hidden` を効かせている。
  フェイスに擬似要素で光沢を足す場合、裏返り中の見え方を1度確認すること。
