### 1-1. ★★★裁定346 の理由(次の人がいちばん蒸し返しやすい)

Batch 59 は本文に「選び」の字が無いことを根拠に、
裁定211(書かれていない限定を足さない)を引いて**選ばせない**と決めていた。

> **このカードゲームで「自動で選ぶ」ということが、そもそも想定されていない。**(マスター)

★**裁定211 は「本文に無い<b>限定</b>を足さない」規則であって、
「本文に無い<b>選択</b>を奪ってよい」規則ではない。**
★★だから直すのは実装の側であり、**本文に「選び」を足して実装を正当化しない** ——
そうすると<b>規則のほうを実装に合わせる</b>ことになる。

## 2. ★76 が実装で決めたこと(裁定を仰がなかったもの)

読みが1つに定まったので、作業を止めずに実装した(リファレンス 1-7 の流儀)。
**間違っていたら戻す。**

| 決めたこと | 根拠 |
|---|---|
| **禁忌デッキ経路の使用条件の抜けは、裁定を仰がずに直した** | 裁定 A6 が「禁忌も通常のプレイと同じ規則を通る」と言っており、これは解釈の問題ではなく<b>写し忘れ</b>である(71 の教訓・片肺)。★影響は**使用条件を持つ9枚すべて** |
| **【賢魂】として使う道には使用条件を掛けない** | 54 の `requireSoul` の Javadoc が「あの表はミニオンとしての姿に紐づく条件である」と明記している。★<b>掛ける場所を、掛かる場所より広く取らない</b>(72 の教訓・幅) |
| 候補が上限以下なら**問わない** | 12b・51 からの流儀である。「選ばない」も選択肢である `upTo` とは別扱い |
| 《光霊・モアニール》で**選んだ個体が既に居なければ、残っている候補を1体壊す** | 1回の解決でリーダーが2度ダメージを受けると問い合わせが2つ積まれ、どちらの候補にも同じ個体が並ぶ。「居ないから何もしない」に落とすと<b>肩代わり1回がただになる</b>。★**失われるのは選択であって、代償ではない** |

| **呼び手を失った器4つを消した** | `turnManaFaceDown` / `turnManaFaceUp` / `returnFaceUpManaToHand` / `destroyFaceDownMana`(裁定178・196。詳細は設計解説6章) |

| **手動モードは1文字も触っていない** | 停止中である(片肺・71 の教訓)。★下の 3-2 に申し送りとして残す |
