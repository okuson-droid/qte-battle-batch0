## 1. 何が問題だったか

商業水準レビュー C-6 の言うとおり、通常モードの盤面は一段古かった。
カードは `.game-card`(青い長方形 + テキスト直書き)で、25〜32c で作り込んだ
カードフェイス(`.mcard-*`)・文明色・質感のどれも使っていなかった。
**同じアプリの中に、カードの見た目が2系統あった** —— 39 がデッキメーカーで
潰したのと同じ構図である(裁定60 の通常モード版)。

## 2. 設計

### 2-1. 面の正は battle.css 1つ。DOM は複製する(裁定111・141)

`battle.js` に手動モードと**同じ DOM・同じクラス名**を出す `cardFace()` を書いた。
コードを共有せず複製したのは 39 と同じ判断である —— 2つの画面は入力の形が違い
(ManualCardView と CardView)、共有できるのは規約だけである。
CSS は 1 行も足していない(`.mcard-*` がそのまま効く)。

### 2-2. ★ミニオンの文明色は card-library から引く(Java 変更ゼロの核)

`MinionView` は文明もテキストも運ばない(現在値と可否だけを運ぶ)。
サーバのビューを太らせる代わりに、**既にある口 `/manual/api/card-library` を
起動時に1回取得し、台帳ID(`cardId` = manual-cards.json の `ledgerCardId`)で引く**。

- ★「サーバの知っているカード」と「画面の知っているカード」の正が1つに保たれる(設計判断28)。
- ★**取得前・取得失敗時でも壊れない**(25 と同じ性質)。文明色が無文明色に、
  拡大のテキストが空になるだけで、対戦は続けられる。
  検証はこれを**実際の 500 応答**で確かめる(42-11)。

### 2-3. ★盤面のミニオン面は「タイル」であり現在値を出す

25 は「フェイスは印刷値」と決めたが、通常モードの盤面ミニオンは
`currentHp/maxHp` を足に出す。これは手動モードの盤面タイル(`.manual-tile`)が
現在値を出すのと同じ意味論であり、「フェイスは印刷値」の例外として明示しておく。
手札・禁忌・拡大は印刷値のままである(実効コストだけ 2-5)。

### 2-4. ★★状態のクラス名は 1 つも変えていない

`playable / can-attack / attack-target / selected-attacker / exhausted /
tapped-minion / mulligan-selected` は `.game-card` 時代の名前のまま、
新しい入れ物 `.auto-card` に付く。**battle.js の状態ロジックには触れていない**
(変えたのは要素の中身だけ)。検証 42-5・42-6 が
「playable → クリックで play-card 送信」「can-attack → selected → attack 送信」を
実マウスで確かめており、これが載せ替えの非回帰の証明である。

- 状態の印はリング(box-shadow)+ 減光(filter)で出す。面の質感(background)には
  触れない(32c: 質感と状態を同じ手段で描くと巻き添えになる)。
- 減光の値 `brightness(0.62)` は手動モードの場のタイルと同じ。
  「行動できない」の見え方が2モードで揃う。
- 一時状態(凍結・タップ・能力・特殊召喚可)はバッジで面の上に重ねる。
  ★位置は**足の上・左寄せ**(頭に置くと名前に被る。目視で確認して移した)。

### 2-5. 実効コストはコストの宝石に出す

`effectiveCost` が印刷コストと違うときは宝石に実効値を出し、
`.mcard-cost-modified`(強調色の輪)で分かるようにした。両方の数字は
`title` と拡大(印刷値)で確かめられる。旧 UI の `<s>5</s>→3` 表記は退役。

### 2-6. 右クリック = 拡大(手動モードの 22 1-7 と同じ規約)

クリックは従来どおり操作(プレイ・攻撃)なので、拡大には別の入口が要る。
手動モードが 22 で「右 = 拡大」と決めているため、同じ規約を通常モードにも敷いた。
出口は クリック / 右クリック / Esc の3つ。カードの上の contextmenu は
preventDefault する(42-7 が実マウスで確認)。

★ハンドラは `oncontextmenu` への**代入**で付ける。リーダータイルのような
使い回しの静的要素にも付けるため、addEventListener だと再描画のたびに積み重なる。

### 2-7. リーダータイルの文明色化

`.leader-card` に `--mc` を JS から注入し、層の順を .mcard と同じ
「光沢 → 縁ハイライト → 文明色の深み」にした。
★`--mc-gloss` を使うため、**41 の宣言セレクタ一覧に `.leader-card` を追加した**
(41 設計解説 3-3 の「使うときは必ずここへ足す」の実行)。

### 2-8. .game-card 一式と escapeHtml の退役

参照ゼロになった CSS(約30行)と `escapeHtml` を削除した。
フェイスは `createElement` + `textContent` で組むため、
エスケープという工程そのものが存在しない(忘れようがない)。

## 3. ★検証 — 自動モードが初めて傘に入った

これまで検証ハーネスは手動モード・ロビー・デッキメーカーの3枚で、
**自動モードは1項目も機械検証されていなかった**。
`build_harness.py` に harness-battle.html を足し、`fixture.js` に
GameView 相当のビルダー(`autoView` 系。フィールド名はサーバの record に一致)を足した。

追加 14項目の骨子: フェイス化(3)/ 実効コスト(1)/ バッジと被弾色(1)/
**状態ロジックの非回帰(2・実マウス)**/ 拡大(3・実マウス)/ リーダー色(1)/
マリガン(1)/ JSエラー(1)/ **取得失敗の退化(1・実 500 応答)**。

わざと壊して落ちることを3通り確認した(文明の結線を切る → 42-2 が落ちる /
preventDefault を外す → 42-7 が落ちる / 失敗を握りつぶさない → 42-11 が落ちる)。

★ハーネスのビューポートは**縦1600px**である。通常モードの盤面は縦に長く(実測 約1400px)、
実マウスはビューポートの外を押せない(高さ900で6項目が「原因不明」に落ちた。
盤面の縦圧縮はタブレット対応=優先順位11 の主題なので、ここでは吸収しない)。

## 4. 確認手順(マスターの手元)

1. **★Eclipse でプロジェクトを refresh(F5)してから起動すること**(直接反映の初回)。
2. スーパーリロード(css v=42 / battle.js v=15)。
3. 通常モードで対戦を開き、手札・場・禁忌がカードフェイスになっていること。
4. **手札を右クリック → 拡大が開き、効果テキストが読めること。** Esc で閉じること。
5. 場のミニオンを右クリック → 文明色つきの拡大にカード定義のテキストが出ること。
6. バトルフェイズで攻撃の選択(黄リング → 橙リング → 対象の赤リング)が今までどおり動くこと。
7. リーダータイルが自分・相手とも文明色になっていること。
8. ★手動モードとデッキメーカーが**何も変わっていない**こと(css の版数だけ動いた)。
