## 0. 目的と背景

現行レイアウトは中央列(840px)の縦積みが約1000pxに達し、実表示域900px前後の
一般的な環境で「手札」か「相手の情報」のどちらかが画面外に溢れる。一方で右列
(224px)は約500pxしか使っておらず余裕がある。

本バッチは以下で解決する。

1. パイル群を右列へ移設し、中央のリーダー行を廃止する
2. リーダーとウェポンを1タイルに合体する
3. ターン/フェイズUIを削除する
4. ログを折りたたみ式(直近2行)にする
5. 新ゾーン PLAY(プレイ中)・PRIVATE(確認)を追加する
6. PLAY・REVEAL をプレイヤー間の共有ゾーンにする

## 2. 変更点詳細

### 2-1. ターン/フェイズUIの削除

ターン数表示・±ボタン・フェイズ名・«»ボタンを**表示ごと削除する**(確定事項Q3)。
`manual-battle.html` の該当行と `manual-battle.js` の該当リスナー・描画コードを消す。

**サーバ側のターン/フェイズ操作(`turn`/`phase` ハンドラとサービスメソッド)は
消さない**(確定事項Q3)。UIから到達できない休眠コードとして残す。design-notesに
その旨を明記し、check系スクリプトの誤検出対象にならないことを確認する。

### 2-2. リーダー+ウェポンの合体

- ウェポン専用スロット(`manual-weapon-slot`・110px幅)を廃止する。
- **リーダータイル自体を WEAPON ゾーンのドロップ先にする。**
  「リーダーにカードを落とす=装備」。
- 装備中のウェポンはリーダータイルの右下に重なるミニタイル(目安 44×60)で表示する。
  ミニタイルのクリックで拡大表示(`setZoom`)、ダブルクリックまたは既存の操作系に
  合わせた方法で数値編集・ラベル・移動の対象にできること(帯と同等の操作性)。
- **ウェポンは1枚制限がゲームルールである**(確定事項Q2)。表示は1枚を前提に組む。
  ただし手動モードは判断を実装しない原則(設計書16 5-1)のため、ゾーンに2枚以上
  入ること自体は妨げない。2枚以上のときはミニタイルに枚数バッジを出して異常が
  視認できるようにする(最前面=リストの先頭を表示)。
- リーダータイルへのドロップと、リーダー自身のクリック(LPモーダル・20a)や
  ミニタイルのクリックが衝突しないよう、イベントの整理を実装時に行う。
- 相手側(B席)も同じ合体タイルを相手上段の右端に置く。B側はドロップ先としても
  機能する(既存のB席ゾーンチップと同じ思想)。

**★実装時の追加確定(マスター確認済み・20b実装チャット)**

- **装備済みでもドロップを受け付ける。** 旧「装備済みの枠には落とせない」規約は撤回する。
  受け付けたうえで、**古いウェポンを自動で墓地へ送る。ただし禁忌由来のものは消滅へ送る**
  (総合ルール2-3)。由来の判定のため `ManualCardInstance.fromTaboo` を新設する。
- **ミニタイルに載せるのは画像と枚数バッジだけとする。** 44×60 に ATK・使用済・札は
  載らない。数値・使用済・札の編集はウェポン操作モーダルへ集約する。
  ウェポンに進化は無いため進化バッジは持たない。

### 2-3. センターライン(プレイ中・公開)— 共有ゾーン

- 中央列の両ミニオン行の間に、左右2分割の帯を常設する。
  左=**プレイ中(PLAY)**、右=**公開(REVEAL)**。
- **この列にあるカードは相手に見えている**、という一貫ルールを画面に与える
  (対戦モードで相手に見せるカードを画面中央に置くのが直感的、という判断)。
- **空のときは高さ24pxの細いドロップバー**(ラベルのみ)。**カードが1枚でも
  入ったら約130pxのストリップに自動展開**し、手札と同等サイズの実カード画像を
  横に並べる。カードが0枚に戻ったら自動で24pxへ畳む。
- ストリップ内のカードは他ゾーンと同様にドラッグ起点・クリック(選択/拡大)・
  数値/ラベル編集の対象になる。
- **PLAY と REVEAL は席ごとではなくゲーム全体で1つの共有ゾーンとする**
  (確定事項・追加指示)。同時に両者が使うことはなく、共有のほうが分かりやすい。
  データモデルは 3章。
- B席のミニチップから「公」を外し、「プ」も作らない(共有ストリップが両者の
  表示を兼ねるため)。B席チップは [山][墓][消][禁][確] の5つになる(2-8)。

### 2-4. 新ゾーンの定義

| enum | 表示名 | 公開範囲(フェーズ2) | 表裏の正規化 |
|---|---|---|---|
| `PLAY` | プレイ中 | 両者に公開・**共有** | 表向きへ正規化 |
| `REVEAL`(既存) | 公開 | 両者に公開・**共有に変更** | 表向きへ正規化(既存どおり) |
| `PRIVATE` | 確認 | **自分のみ**(相手には枚数のみ) | 表向きへ正規化 |

- `ManualZone` に `PLAY`・`PRIVATE` を追加する。
- 20aの `FACE_UP_ON_ARRIVAL` に `PLAY`・`PRIVATE` を追加する
  (追加後: FIELD/WEAPON/TRASH/LOST/REVEAL/HAND/PLAY/PRIVATE)。
  PRIVATE は「自分が中身を見ている」状態のゾーンであるため表向きが自然。
  フェーズ2で相手に隠す処理はゾーンフィルタの責務であり、faceDown と混同しない。
- `ZONE_LABELS`(JS)に プレイ中/確認 を追加する。
- 用途例: PRIVATE =「山札の上から3枚を見て1枚を手札に加える」→ 山札の全面表示
  から3枚を確認パイルへドラッグ → 確認パイルをクリックして帯で閲覧 → 1枚を手札へ、
  残りを山札の上/下へ。PLAY = スペルの効果解決中の一時置き場(ミニオンは場に
  直接出すため対象外だが、置くこと自体は妨げない)。

### 2-5. ログの折りたたみ

- `log-box` を高さ約40px(直近2行ぶん)に縮める。
- クリックで**右列内でその場拡張する**(確定事項Q6)。拡張時は下方向へ伸ばし
  (目安300〜400px)、宣言ボタン行を押し下げる。再クリックで畳む。
- 自由メモ入力・ログ書き出しは従来どおり。

### 2-6. パイル群の右列移設とカード画像化

- 対象: 山札(DECK)・墓地(TRASH)・消滅(LOST)・禁忌(TABOO)・確認(PRIVATE)。
  ※公開(REVEAL)はセンターラインへ移ったためパイルではなくなる。
- **並び順(確定)**: 上段 [禁忌][山札][確認]、下段 [消滅][墓地]。
- パイルは**カード型(90×126)にカード画像を敷いた見た目**にする。
  - 山札・禁忌(非公開パイル): 裏面画像(`backImageId`)
  - 墓地・消滅・確認: 一番上のカードの表画像。0枚のときは破線の空枠
  - 枚数バッジをカード画像の角に重ねる。ラベル(ゾーン名)はカードの上か下に添える
- 既存の操作系は維持する:
  - 山札: 左クリック=1枚ドロー / 右クリック=全面表示 / ドラッグ=一番上の1枚
    (20a) / シャッフル / 上へ・下へ
  - 墓地・消滅・禁忌・確認: クリック=帯表示、ドロップ先
- **山札のシャッフルボタンと「上へ/下へ」枠は、パイル画像の直下に常時表示で
  添える**(★設計判断: ホバー時のみ表示の案は誤操作・気づきにくさの点で退けた。
  右列は縦に余裕がある)。
- 20a 3-1の「上へ/下へ枠・ボタンを掴んでも山札ドラッグが始まらない」対策
  (`document.elementFromPoint` 判定)は、パイルの入れ物構造が変わっても
  維持されること。20a 3-2の `stopPropagation` 前提も同様。

### 2-7. ヘッダの1行化

部屋コード・接続状態・ボタン群を1行に収める。折り返しは許容
(`flex-wrap`)するが、通常の画面幅では1行で収まる密度にする。

**★実装時の追加確定(マスター確認済み)**: 在室者リスト(`#occupant-list`)と
デッキ読み込みステータス(`#deck-import-status`)も、このヘッダ1行に統合する。

### 2-8. B席(相手上段)の構成

左からミニチップ [山][墓][消][禁][確](枚数付き・ドロップ先)、右端に
リーダー+ウェポン合体タイル。チップのクリックで帯表示(既存どおり)。
確認(PRIVATE)チップはフェーズ1では中身も見える(一人回しのため)。フェーズ2で
枚数のみになるのはゾーンフィルタの責務(本バッチでは実装しない)。

## 3. 共有ゾーンのデータモデル(★サーバ設計)

### 3-1. 方針

`ManualGameState` に**ゲームレベルの共有ゾーン置き場**を追加する。

```
ManualGameState
  ├─ seatA: ManualSeatState (zones: DECK/HAND/MANA/FIELD/WEAPON/TRASH/LOST/TABOO/PRIVATE)
  ├─ seatB: ManualSeatState (同上)
  └─ sharedZones: Map<ManualZone, List<ManualCardInstance>>  // PLAY, REVEAL のみ
```

★席の下に置く「慣習方式」(常にA席のzonesへ格納する等)は、モデルとして嘘になり
将来の読み手を混乱させるため退けた。部屋はメモリ上にのみ存在し永続化が無いため、
データ移行の問題は発生しない(デプロイ再起動で部屋は消える)。

### 3-2. 影響範囲

- `move` 操作: `toZone` が PLAY/REVEAL のとき `toSeat` を無視して共有ゾーンへ
  入れる。取り出し(検索)も同様に共有ゾーンを探索対象に含める。
- 既存の REVEAL 参照箇所(帯・パイル・B席チップ・ビュー)をすべて共有側へ付け替える。
  **「反映済み」を信じず、`REVEAL` の全参照をgrepで洗い出して1件ずつ移すこと。**
- `ManualGameView` に共有ゾーンの項を追加する(例: `shared: { PLAY: [...], REVEAL: [...] }`)。
  JS側は `view.shared.PLAY` 等を読む。
- undo/redo のスナップショットが `sharedZones` を含んで複製されることを実装時に
  必ず確認する(スナップショット機構の実装方式に依存するため要注意ポイント)。
- 20aの表裏正規化(`normalizeFaceDown`)は共有ゾーン行きの移動にも適用されること。

**★実装時の追加確定(マスター確認済み)**: `loadDeck` / `resetRoom` の両方で
共有ゾーンを全消去する。`ManualCardInstance` は持ち主を持たないため「A席由来だけ
消す」は書けず、放置すると山札へ戻らない個体が中央に残るためである。

### 6-3. センターライン展開時の高さ

展開時に900px級の画面でわずかに溢れる場合、ストリップ内カードの高さを
110px程度へ縮める調整余地を残す。
