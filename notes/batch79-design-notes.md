## 1. ★★★原因 —— `setInputFiles` は「change を投げたところ」で返る

```js
document.getElementById('in-deck').addEventListener('change', async ev=>{
  const f=ev.target.files[0]; ev.target.value=''; if(!f) return;
  try{ importJsonDeck(JSON.parse(await f.text())); }   // ★ここで一度手を離す
  catch(e){ toast('デッキの読み込みに失敗: '+e.message); }
});
```

Playwright の `setInputFiles` は<b>ファイルを載せて `change` を投げたら解決する</b>。
ハンドラが `await f.text()` で手を離した先まで待つ約束はどこにもない。
★verify は返ってきた直後に `evaluate` で DOM を読むので、
<b>まだ組み立てが終わっていない画面</b>を読むことがある。

★★<b>証拠が毎回 `{"main":"7/40", ...}` だったのは、それが「読み込む前の組みかけ」だからである</b> ——
78 の申し送りの見立て(「デッキの組み立てが終わる前に読んでいる」)は当たっていた。

### 1-1. ★★★頻度ではなく原因を測った

★76・77・78 は<b>落ちた回数</b>を記録してきた(1回 / 1回 / 4回中2回)。
★★<b>回数は測っても仕方がない</b> —— 箱の速さ・同時に走っている仕事の量で動くからである
(74 の教訓「シャッフルに依存する試験は番人ではない」の、**測る側**の版)。

★★★そこで<b>決定的に再現させた</b>。`File.prototype.text` の解決を n ミリ秒遅らせて同じ手順を踏む:

| 遅らせた量 | 直後に読んだ値 |
|---|---|
| **0ms** | `{"main":"40/40","taboo":"8/8","chip":"検証OK"}`(通る) |
| **5ms** | ★`{"main":"7/40","taboo":"0/8","chip":"検証2 件"}`(**落ちる**) |
| 20ms / 60ms / 400ms | 同上(**落ちる**) |

> ★★★**余裕は5ミリ秒しかなかった。**
> 78 で頻度が上がったのは実装が変わったからではなく、**箱が忙しかったから**である。

## 2. ★★★直し方 —— 時間で待つのをやめ、事実で待つ

### 2-1. 待ちの器を1つにした(`settled`)

```js
async function settled(page, fn, arg, timeout = 5000) {
  try { await page.waitForFunction(fn, arg, { timeout, polling: 25 }); return true; }
  catch (e) { return false; }
}
```

★**時間切れでも投げない。**`false` を返して、呼び出し側は<b>そのまま測って赤を出す</b>。
★★<b>投げると検証スクリプトごと死ぬ</b>(72・75 の教訓・**死ぬ検証は番人ではなく無音である**)。
★★★<b>だから「待てなかったこと」も証拠に載せる</b> ——
時間切れの赤と、値が違う赤を、読む人が区別できるようにするためである。

### 2-2. ★何で待つかは「測っている値と別の事実」を選ぶ

| # | 待つ事実 | なぜそれか |
|---|---|---|
| V5 | `#toast` の本文が空でなくなる | ★<b>`toast(...)` は `importJsonDeck` の最後の1文である</b> —— 「ハンドラが最後まで走った」ことそのものを表す。★★<b>落ちていた2項目はどちらも toast を読んでいない</b>ので、待ちと測りが同じ値にならない |
| V6 | `#deck-gate-file` の `dataset.busy` が消える | ★★<b>器は既に在った</b> —— `battle.js` が `finally` で消している(66 から)。65 の教訓「番人が無いと思ったら、まず在るかどうかを見る」の**待ち方版**である |
| V4 | `#manual-toast` の本文が空でなくなる | 出ること(待つ)と<b>何と書いてあるか</b>(測る)を分けた |
| V2 | `window.__fetched` が1件以上になる | 呼ばれたこと(待つ)と<b>何を送ったか</b>(測る)を分けた。ゲートが閉じることは別に `settled` で待つ |

★★<b>待つ相手と測る相手が同じになるのは避けたが、避けきれない場合もある</b>
(V2 のゲート閉じ)。★そのときは<b>上限つきの待ち</b>で足りる ——
壊れていれば時間切れになり、時間切れは<b>赤</b>である(無音ではない)。
