## 2. ★★★設計書から動かしたところ(2件)

### 2-1. 段の長さの表を「作らなかった」

設計書 4-2 は「段が語ること → 長さ」の表を示し、
★**「定数を新しい表に写さない。写すと正が2つになる」**と釘を刺していた。

★★実装は**表そのものを作らなかった**。
`fxRegister(key, el, ms, ...)` は**すべての演出が必ず通る1箇所**なので、
そこを通った `ms` の最大値を控えるだけでよい。

```js
if (ms > fxSpawnMs) fxSpawnMs = ms;      // fxRegister の中
...
const ms = stepTune(fxSpawnMs);          // 段の長さ
```

★★★**演出の長さを変えた日に、段の長さも黙って追随する。**
★<b>「写さない」の一段上は「読む場所を1つにする」である</b>。

★演出が1つも走らなかった段(ログ行だけの段)は `fxSpawnMs` が 0 のままなので、
`stepTune` が `STEP_MIN_MS`(200ms)まで持ち上げる —— 裁定369(盤面が動かない段も再生する)。

### 2-2. ★★★最終状態のあとに待つかどうかを、後ろで決めるようにした

初版は「最終状態のあとは待たない(直前の段が既に間を持っている)」と書いて実装した。
★★**壊し検証の軸9 が、それが誤りであることを教えた。**

<b>次の操作の段がキューに積まれていると、その操作の結末が0ミリ秒だけ映って消える</b> ——
★<b>畳んだときの最終状態は残りの変化を全部背負っている</b>ので、
**いちばん見せなければならない一枚が、いちばん見えないことになる**。

```js
if (item.final && stepQueue.length === 0) { /* 待たない */ }
```

★**誰も待っていないなら待たない**(その操作はもう終わっており、人を止める理由が無い)。
★★**後ろに次の操作の段が居るなら、最終状態も1段として待つ。**

> ★★★**NG は「番人が足りない」だけでなく「実装が足りない」ことも教える**
> (83 の教訓の、実装の側の顔)。

## 3. ★演出を切っている人には段を再生しない

設計書 4-4-3 は `prefers-reduced-motion` だけを挙げていたが、
実装は `fxAllowed()` をそのまま使った —— ★**演出の設定オフも同じ扱いになる**。

★★**理由**: 演出を切っている人に段だけ再生すると、
<b>何も動かないまま待たされるだけになる</b>。
★これは裁定358「演出を切っている人には出さない」と同じ形であり、
**新しい規則ではなく既存の規則の適用である**(採番していない)。

★★★**これは「飛ばし」ではない**(裁定364)——
飛ばしは**人が演出を打ち切る出口**であり、こちらは**そもそも再生しない**である。

## 7. ★積み残し・気づいたこと

- ★★**`filter` は使えない。**盤面を沈めるのに `filter: brightness()` を掛けると、
  <b>`position: fixed` の包含ブロックが変わって fx 層の座標が丸ごとずれる</b>。
  ★`opacity` だけで沈めてある。**次に「暗くしたい」と思った人はここを読むこと。**
- ★**壊し検証を2並列で回したとき、いちど EMPTY が出た**(軸1)。
  ★★<b>単独で回すと OK、その後 2並列でも再現しなかった</b> ——
  <b>verify を11本並べたときの揺れであり、実装の問題ではない</b>。
  ★<b>EMPTY が1回出たら、まず単独で回し直すこと</b>(82 の「NG が全部なら測っている場所を疑う」の親戚)。
- ★★**観戦者が増えると段の配信量は線形に伸びる**(84a 2-3)。上限は現在どこにも無い。
