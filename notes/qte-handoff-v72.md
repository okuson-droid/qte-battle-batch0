## ★★65 がやったこと(要点)

設計解説は **`notes/batch65-design-notes.md`**(新規)。

### 1. ★★★測ってから読んだ

マスターの指定は「通常モードの UI の修正・改善」だった。まず**満杯の盤面を作って測った** ——
マナ15枚(ゾーンの上限)・場6体ずつ・手札11枚。その結果いちばんはっきり壊れていたのが
**マナ行**である。

| 盤面 | はみ出し | 最小の露出 |
|---|---|---|
| 15枚・タップなし | 0px | 41px |
| 15枚・3枚に1枚タップ | 0px | **33px** |
| 15枚・すべてタップ | **+50px** | 65px |

★**マナ15枚すべてタップ済は端の盤面ではない。**アンタップは自分のターンにしか起きないので、
終盤に MP を使い切れば**相手のターン中ずっとその姿が映る**。

### 2. ★★★壊れ方は3つあった

| # | 壊れ | 中身 |
|---|---|---|
| 1 | 回転の外接を勘定に入れていない | タップ済は見た目の外接が 80px。`scrollWidth` はレイアウト幅しか見ない |
| 2 | 重なりが枚数に依らない | 固定 **-26px**。12枚では過剰、15枚では足りない |
| 3 | ★**下駄が詳細度で負けていた** | `.tapped { margin-left: 14px }` が `.auto-mana-overlap`(クラス4つ)に負け、**一度も効いていなかった** |

3 がいちばん質が悪い。**吸うための下駄はちゃんと書いてあった**のに、
重なり側のセレクタのほうがクラス1つぶん詳細で、勝ち負けが挙動を決めていた。

> **同じ性質の値を CSS と JS の両方に置くと、挙動を決めるのは「意図」ではなく「詳細度」になる。**

### 3. ★★★同じ症状は手動モードが 34 で直していた

`applyManaOverlap`(手動モード)の Batch 34 hotfix のコメントに、**同じ根**が書いてある ——
「タップ済のタイルは占有幅が 88px なので……15枚すべてタップ済だと右列を約 480px はみ出していた」。

手動モードは 34 で直り、通常モードのマナ行は 43〜45 で**新しく作られた**ので継承しなかった。

> **「簡易版」と書いた実装は、本家が直っても自分では直らない。**

★64 の教訓(「暫定でこうしておく」は前提が消えても戻らない)の**空間版**である ——
64 は時間、65 は空間。どちらも「**自分では戻らない**」を指している。

### 4. どう直したか

- CSS から `.auto-mana-row` 系の margin を**全部**外し、`gap: 0` を明示した。
  規則は `battle.js` の **`applyAutoManaOverlap` 1本**である。
- 規則は手動モードと同じ3つ ——
  **占有幅はタイルごとに違う / 必要なぶんだけ均等に重ねる / 露出の下限を守る**(28px → 14px)。
- `.auto-mana-overlap` クラスは使い手を失ったので撤去した(裁定178)。

**結果**: どの組み合わせでも**はみ出し 0px**。15枚混在の露出は **33px → 57px**。

### 5. ★手動モードとの1点の違い(意図的)

重なりの上限を取る対象は、`z-index` を昇順に振る以上**覆われる側**(`0 〜 n-2`)である。
**手動モードは覆う側(`1 〜 n-1`)で取っている。**均一な行では同じ値だが、
タップ済と非タップが混ざる行では1枚ぶんずれる。

★**65 は手動モードを触っていない。**題は通常モードの UI であり、7305行の
`manual-battle.js` と手動モードの verify を巻き込むのは題を広げすぎる。**積み残しに書いた。**

### 6. ★★verify は実装の定数を1つも書いていない(裁定298)

測るのは**ブラウザが置いた矩形から出てくる不変量**2つだけである。

- **はみ出さない** …… 一番右のタイルの `right` が行の内容box を超えない
- **重なりが均等** …… `(隣までの距離 - 実測幅)` が全ての隣接対で等しい

★**実測幅を使うのが肝**である。回転したタイルの幅はブラウザが 80px と答えてくれるので、
検証の側に「回転しているから 80」と書かずに済む。
★重なりの前後は `z-index` を読まず **`elementFromPoint`** で測る(裁定296)。

### 7. ★自分で二重の番人を書きかけた

「`battle.css` を読み込むテンプレートの版数が揃っていること」を新しい verify として書いたら、
**Batch 36 が同じものを既に持っていた**(`const cssVersions` の二重宣言で Node が拒んで気づいた)。

> **「番人が無い」と思ったときは、まず在るかどうかを見る。**

### 8. ★壊し検証の JS 版(裁定304 に壁が無い)

64 は「条件を落とす」改変が**到達不能でコンパイルを拒まれ** EMPTY になった。
**JavaScript には同じ壁が無い** —— 黙って別物が動く。これは「壊しすぎて測れない」よりも
見えにくい。だから 65 の改変は、文を消して後続を宙に浮かせる形を1つも使っていない
(式ごと置き換えるか、**常に偽になる条件**で包む)。
