## 1. カードマスタの差し替え

### 1-1. keywords はファイルに無い ―― テキストから作る

`manual-cards.json` に `keywords` フィールドは存在しない(Batch 24 hotfix2 で廃止。
**テキストが正**)。そこで `CardMasterRepository` の DTO は

```java
return new CardMaster(id, name, CardType.valueOf(type),
        Civilization.valueOf(civilization), cost, attack, hp,
        CardTextKeywords.extract(text), text);
```

とだけ書く。**抽出結果をどこにも保存しない**(裁定158)。表を持った瞬間に
「テキスト」と「表」という2つの正ができる。

★この1行が正しく効いていることは、テスト
`リポジトリのキーワードは全235枚が抽出規則の出力そのものである` が測っている。
人手の表を途中に挟むと落ちる。

### 1-2. `ledgerCardId` を `CardMaster` に持たせない

読み飛ばすのは `ledgerCardId` だけではない。`imageId` と `unlimitedCopies` も
`@JsonIgnoreProperties(ignoreUnknown = true)` のまま**受け取らない**。

**エンジンが使わない項目を record に足すと、「使えるから使ってしまう」経路が開く。**
画像は画面側が `/manual/api/card-library` から引く(裁定144 と同じ形)。
`ledgerCardId` は退役するIDであり、新しい正に持ち込むと2つのIDが並走し続ける。

台帳との対応が要るのは**移行作業とそれを検める試験だけ**であり、
どちらもファイルを直に読めばよい(`tools/build_id_map.py` / `CardIdMappingTest`)。

### 1-3. `qte-cards.json` は削除していない

46b では**読まなくなるだけ**である。理由は2つある。

1. 1バッチ分の戻り道を残す。
2. **抽出規則の番人がまだあのファイルを必要としている**(下の 3-1)。

## 2. 機械変換 ―― 169種・469行

```bash
python3 tools/build_id_map.py --sed > /tmp/idmap.sed
grep -rlE "QTE-(0[0-9]{3}|L[0-9]{3}|X[0-9]{3})" src/main/java src/test/java \
     src/main/resources/static/js | xargs sed -i -f /tmp/idmap.sed
```

対応の出どころは `manual-cards.json` の `ledgerCardId` **1つだけ**である。
`build_id_map.py` は出力の前に全単射であることを確かめ、崩れていれば終了コード1で止まる。

変換後、Java・JS に残る台帳IDは **0件**。`build_id_map.py --check` の
「Java にベタ書きされた台帳ID: **0 種**」がその証拠である。

### 2-1. ★機械変換が1件だけ誤爆した

`ManualCardMasterLoadTest` の

```java
assertThat(card.ledgerCardId()).isEqualTo("QTE-X001");
```

は、**手動モードのカードが持つ台帳IDそのもの**を測っている行であり、
ここを書き換えたら意味が反転する(「台帳IDが台帳IDでなくなる」)。

**★機械変換は「その文字列が何を指しているか」を知らない。**
一括置換をかけたら、必ず差分を1ファイルずつ読むこと。
今回は `git diff` を読んで気づき、このファイルだけ `git checkout` で戻した。

### 2-2. verify のフィクスチャも変換対象だった

`verify/verify.js` `verify/fixture.js` `verify/autoshot.js` にも台帳IDが埋まっている。
これらは「サーバが送ってくるビュー」を模した固定データであり、
**本番のIDが変われば一緒に変わらなければならない**。同じ sed を当てた。

## 3. テストの再編

### 3-1. ★台帳との169枚照合を残した(マスター裁定)

照合は続けられる。マスター裁定により**残す**ことにした。

- 新設: `src/test/java/com/example/qte/support/LedgerCards.java`
- ★これは「2つ目の正」ではない。台帳はもう何の正でもなく、**凍結した過去の断面**である。
  使い道は1つ、抽出規則を触ったときに169枚の解釈が黙って変わっていないかの検出だけである。

- ★`qte-cards.json` を削除するバッチで、`LedgerCards` と台帳を見る3件のテストを

### 3-2. ★照合の右辺を「規則の出力」から「エンジンが持つ値」へ移した

46a の時点では本体がまだ台帳を読んでいたので、`CardTextKeywords.extract()` を
直接叩いて比べるしかなかった。46b からは**リポジトリが実際に持っている値**を測れる。

**規則が正しくても、配線を間違えれば挙動は変わる。** 測るべきは配線の先である。

### 3-3. `DeckValidatorTest` を新設した(8件)

このバッチで一番効く番人である。

**プリセットデッキ6本を検証層に通す。** `DeckFactory` に書かれた **151行ぶんのID**が

さらに「選択できるリーダー18枚すべてでプリセットが通る」も測る
(★46b でリーダーが12枚から**18枚**に増えた)。

### 3-4. `CardMasterLoadTest` に「退役した台帳IDでは引けない」を足した

**差し替えたことの一番はっきりした証拠**である。もし台帳IDが引けるなら、

## 4. ★同名無制限(ゾンストライカー)は Ver1.1 で消えていた

`DeckValidator` の `UNLIMITED_COPIES = Set.of("QTE-0012")` を撤廃した。根拠は本文である。

| | 本文 |
|---|---|
| 台帳(Ver0.4) | 【召喚時】「ゾンストライカー」を墓地から全て出す。**このカードは4枚以上入れられる。** |
| Ver1.1 | 【召喚時】「ゾンストライカー」を墓地から全て出す。【突進】破壊されたとき自分の山札の上から1枚を墓地に置く。 |

**Ver1.1 で「4枚以上入れられる」の一文が消え、代わりに【突進】と【破壊時】が付いた。**
したがって例外を持つカードは235枚中**0枚**である。

### 4-1. ★闇のプリセットが5枚入れていた(移行が掘り出した不整合)

`DeckFactory.DARK_STARTER` はゾンストライカーを **5枚**入れており、
例外表に頼っていた。例外を撤廃した瞬間、闇のプリセットが検証を通らなくなる。

**5枚 → 4枚にし、減らした1枚は腐敗の投擲者(2コスト)に振り替えた。**
ミニオン28枚・ウェポン3枚・スペル9枚という構成は保っている。

★`DeckFactory.validate()` にも同じ例外が書かれていた(`count > 4 && !"QTE-0012".equals(...)`)。
**同じ規則が2箇所にあると、必ず片方だけが直される日が来る**(裁定130)。両方消した。
`tools/check_all.py` の `UNLIMITED` も空集合にしてある —— 空にしておくと、
例外が復活したときにここが落ちる。

## 5. 進化ミニオンはデッキ構築で弾く(裁定166)

`DeckValidator` に `requireDeckable(card, where)` を1つ置き、
メインと禁忌の**両方**から呼ぶ。

```java
if (card.type() == CardType.EVOLUTION) {
    throw new IllegalArgumentException(
            "進化ミニオンはまだ通常モードで出せないため%sに入れられません: %s"...);
}
```

**効果未実装のミニオンは「出せるが何も起きない」で済むが、進化は場に出す手段そのものが無い。**
素材の指定・下に置く構造・場を離れるときの同伴(裁定154)はどれも未実装であり、実装は P3(54〜55)である。
入れると手札で完全な死に札になるので、裁定D2 の「印つきで入れられる」の趣旨から外れる。

★片方の経路だけ塞いで安心しないよう、**禁忌デッキ側にも試験を置いた**
(水リーダーには火の進化を入れて測る)。

## 7. `battle.js` ―― 索引の鍵を `id` に変えた(版数 v=19)

```javascript
- if (c.ledgerCardId) autoLibrary.set(c.ledgerCardId, c);
+ if (c.id) autoLibrary.set(c.id, c);
```

**★これが 46b の目に見える実利である。** 45 までは索引の鍵が `ledgerCardId` だったので、
**台帳に相手のいない新カード66枚は索引に一切入らなかった**
(色は無文明色、拡大のテキストは空)。鍵を `id` に変えると、同じ経路でそのまま出る。

新設の検証項目(46b-1)が、実際に新カード(分那愚利)の文明色が土の色になることを測る。
索引の鍵を戻すと、この項目だけが落ちる。

版数は **battle.js v=18 → v=19**。`verify/build_harness.py` の置換文字列も同時に直した
(片方だけ直すと、ハーネスが `battle.js` を読み込まなくなり、検証スクリプトごと死ぬ。5-2 参照)。

### 8-5. ★★穴を1つ見つけて塞いだ(裁定135 と同じ形)
