## 1. 仕分けの固定(`tools/rework_triage.py`)

### 1-1. 機械的な再現は境目でぶれる

rework-triage.md 1-1 節の畳み方(キーワード表記除去→記法の畳み込み→類似度)を
Python で素朴に再現したところ、区分1は33〜48枚・区分2は3〜4枚と、
仕分けのたびに結果がぶれた。原因は「コストNを支払う。」の省略や「枚」の増減など、
細部の表記ゆれの畳み方が一意に定まらないためである。

★**結論: rework-triage.md 4章の確定カード一覧を、そのまま `tools/rework_triage.py` の
データとして固定した。** 以後は畳み方を毎回再計算せず、この表だけを見ればよい。

### 1-2. 《大地の精霊 グラン》の保留を解消した

rework-triage.md 4章で「区分4と重複しないよう55で確認」と保留になっていたカードである。
`CardEffectRegistry` を確認したところ、旧本文にトリガーの明記が無いだけで、
実装は既に `TriggerType.ON_SUMMON` として登録済みだった(コード: `QTE-M-EARTH-3`)。
新本文の【召喚時】明記は**効果を変えていない**。

★結論: 区分3bに残すが、**実装変更は不要**(Batch 56 は確認だけでよい)。

## 2. 着手前の4件の食い違いを直した(rework-triage.md 2章)

`【起動：n】` のnと `CardEffectRegistry.leaderAbilities` の `mpCost` を突き合わせた結果、
3枚のコストが旧本文の書き落としのまま0で実装されていた。

| カード | 直した内容 |
|---|---|
| 蒼海の賢者(QTE-M-WATER-1) | `mpCost` 0 → **1** |
| 傷痕の闘帝(QTE-M-FIRE-15) | `mpCost` 0 → **1** |
| 冥府の禁皇(QTE-M-DARK-1) | `mpCost` 0 → **1**(★効果自体は56に残す。同じカードに55と56が二度触る) |
| 剛火の将(QTE-M-FIRE-1) | **起動能力の登録を削除**(Ver1.1で本文から丸ごと消えたのに登録が残っていた) |

### 2-1. 剛火の将は「効果未実装」の印が付くようになった

死んだ登録を削除した結果、`isRegistered()` が false を返すようになり、
新本文の常在効果(【速攻】持ちのHP+2)が未実装のカードとして印が付いた。
これは**正しい挙動変化**である —— 「持っている処理が古い」場合は印が表せないが
(裁定165)、「処理そのものが無くなった」今回のケースでは印が付くのが正しい。

`EffectImplementationTest` の不変条件テストをこの状態に合わせて書き換えた
(`効果未実装のカードは1枚も無い` → `効果未実装のカードは剛火の将だけである`)。
常在効果の実装は Batch 57(区分5)の範囲であり、それまでこの1枚だけが未実装のままになる。

### 2-2. 番人 `tools/check_leader_abilities.py`

rework-triage.md 2-2 節の指示どおり、同じ形の照合を `tools/` に残した。測るのは:

1. `【起動：n】` の n と `leaderAbilities` の `mpCost` の一致。
2. テキストに `【起動】` が無いのに `leaderAbilities` に登録があるもの(死んだ登録)。

★《流転の智者》(QTE-M-WATER-15)のテキストが `【 起動：2】` と【の直後に半角スペースが
入った表記ゆれを持っていた。データは書き換えず、正規表現側で吸収した(裁定257と同じ判断)。

## 4. 区分3a(13枚)の実装

数値の差し替えが中心だが、2枚だけ構造が変わった。

| カード | 変更 | 備考 |
|---|---|---|
| 命を削る烈火 | 全体ダメージ 2→3 | 定数のみ |
| 相打ちの咎人 | 相互ダメージ 1→2 | 定数のみ |
| 背水の炎壁 | 特殊召喚コスト 0→1 | 【守護】はテキストから自動 |

### 4-1. アクア・サーチ: `PendingChoice.one` から `min=max=2` へ

旧実装は `PendingChoice.one`(単一選択)だった。2枚捨てに対応するため、
`new PendingChoice(kind, candidates, 2, 2, ...)` に直接組み立てる形にした。
解決処理(`AQUA_SEARCH_DISCARD`)は、複数選択を位置の降順で削除する形に書き換えた
(《詠唱の疾風騎士》と同じ形。位置がずれないようにするため)。

★手札が2枚に満たない場合(山札切れ等)は `Math.min(2, handPositions.size())` で
「あるだけ全部」に切り替える。

### 4-2. 冥府への道: 要求数を1→2に、`playConditions` も2体以上へ揃えた

新本文は「相手のミニオンを2体選び破壊する」であり、単純に要求数を2に上げた。
相手の場に1体しかいない場合の扱いが裁定候補に挙がっていない(区分3aは裁定不要枠)ため、
**既存の「N体選ぶ」系スペルと同じ、要求数=最小要求の形**を踏襲した ——
`playConditions` を「相手の場に2体以上」に揃え、1体のときは使用そのものを弾く。

既存テスト `DarkLightVer11EffectTest.キーパーは場で破壊されたときは戻らない` が
《冥府への道》を1体破壊の道具として使っていたため、相手の場にもう1体添える形に直した
(裁定どおり、Ver0.4の挙動を測っていた試験は書き換えるのが正しい)。

## 5. 壊し検証(8通り)

`tools/batch55_break_check.py`(JUnit 7通り)+ `check_leader_abilities.py` 自体の
検出力の確認(1通り)= **8通り。★1回目は NG 1件。それ以外は8/8 OK。**

### 5-1. NG 1件が教えたこと —— HP1のミニオンでは2ダメージと3ダメージが見分けられない

《命を削る烈火》の全体ダメージ2→3を壊す検証で、対象に《ウィンド・ペティ》(HP1)を
使っていたところ、ダメージが2でも3でも「破壊される」という結果が同じになり、
壊しても試験が落ちなかった(裁定196の「同じ結果を2つの理由で得られる試験」)。

HP3の《ディープシー・シャーク》に差し替え、実際の残りHPで見分くようにして OK になった。
★54の壊し検証で見つかった教訓(「同じ語を含む2つの理由を1つの試験で測らない」)の
親戚である ——今回は「同じ結果になる2つの入力を1つの試験で測らない」。

### 5-2. `check_structure.py` の警告

4件の食い違い修正のコメントを足したことで `registerDarkCards()` が一時的に
閾値(300行)を超えて△要確認になった。コメントを圧縮して解消した
(運用ルール「既存カードの写しで済むものは表に1行でよい」の適用)。
