### 2-1. 出来事 → 演出の対応表

### 2-2. ★★★「複製」で動かす(本物は動かさない)

★攻撃者・破壊されるミニオン・着地するミニオンは、<b>本物を写した複製</b>を演出の層に置いて動かす。

- ★★<b>破壊と消滅は、本物がもう居ない</b>(段のビューでは場から消えている)。
  ★<b>描く前に旧位置と要素を控え</b>(`fxStoryCapture`)、描いたあとにその位置へ複製を置く ——
  80 の「読む相と書く相を分ける」をそのまま使った。
- ★<b>攻撃者を本物のまま動かすと、盤面の行の外へ突進できない</b>(リーダー欄は右の列にある・裁定371)。
  ★本物は複製が動くあいだ `auto-fx-hold`(`visibility: hidden`)で隠し、終わったら戻す。
  <b>場所は空けたまま</b>なので、盤面の並びは動かない。
- ★★<b>複製からは `id` と `data-instance-id` を剥がす。</b>剥がさないと、演出のあいだ
  `getElementById` / `querySelector` が<b>複製のほうを引く</b>ことがある(描画が複製へ書き込む)。
- ★★<b>本物には子を足さない。</b>ダメージの赤い膜は、本物の上に<b>層の側で矩形として</b>重ねる(`flashAt`)。
  本物へ子を足すと、描画の側の前提(`:last-child`・position)を黙って変える。

### 2-3. ★★拍と余韻 —— 段の長さに入れるもの

★段の長さは `fxRegister` を通った ms の最大値から決まる(84b 2-1)。
★★<b>演出の長さの正は `QteFx.MS` の1箇所</b>であり、`battle.js` は同じ値を `fxRegister` へ渡す ——
<b>数字を2箇所に書かない</b>(演出の長さを変えた日に、段の長さも黙って追随する)。

| 拍(`QteFx.MS`) | ms |
|---|---|
| `ATTACK`(溜め 300 → 突進 150 → ヒットストップ 80 → 戻り 420) | 950 |
| `NUMBER`(数字が浮いて消えるまで) | 800 |
| `DEATH`(ひびと震え 520 → 砕けたあとの間 420) | 940 |
| `BANISH`(光に包まれ 360 → ほどけて昇る 520) | 880 |
| `SUMMON`(浮き上がり 260 → 溜め 200 → 叩きつけ 170 → 弾み 260) | 890 |
| `CAST`(詠唱位置へ 420 → 収束 620 → ほどける 160) | 1200 |
| `BOLT`(詠唱位置 → 対象) | 480 |
| `BANNER`(帯テロップ) | 1150 |

★★<b>破片の飛散・粒子・焦げ跡は「余韻」であり、段の長さに入れない。</b>
余韻まで入れると、破壊1体で段が 1.8 秒になる。★余韻は自分で消える(破片と焦げ跡は setTimeout、粒子は寿命)。
★<b>拍 = 「次の段を始めてよくなるまで」</b>である。

### 2-4. ★★呪文の弾 —— 詠唱位置を段をまたいで残す

★サーバは呪文の効果を<b>別の段</b>に分けて送る(1章)。★ダメージの段だけを見ると「どこから来たか」が分からない。

- ★★<b>残すのはその操作の解決の間だけである</b> —— 攻撃・ターン・決着・<b>最終状態</b>で捨てる。
  次の操作のダメージを、前の呪文の弾として描かない(番人 85b-15・軸13)。
- ★デモは呪文ごとに演出名(fireball / chain / heal / buff)を持っていたが、★<b>QTE の235枚は効果を1つも名乗らない</b>。
  名乗らせると<b>カードの正が2つになる</b>ので、後半は「詠唱位置から対象へ弾を飛ばす」1つで語る。
  ★弾の色は呪文の文明の色である(`--civ-*` から変換した・色の表を新しく作らない)。

### 2-5. ★★★画面揺れ(裁定375)—— 閾値は 5

★裁定375 は「大きい」の閾値を 85b に預けていた。★<b>`FX_SHAKE_DAMAGE` = 5</b>(この値以上のダメージで揺らす)。

- ★<b>揺らすのは大きいダメージだけである。</b>デモは召喚の着地と破壊でも揺らしていたが、裁定375 の文言に合わせて外した。

  ★`translate` にしたのは、盤面の `transform`(ホバーの持ち上げ等)を上書きしないためである。

### 2-6. ★★ドロー —— 席ごとに1本の演出にまとめる(裁定377)

★開始の配りは<b>1段に DRAW が9件</b>来る(自分4・相手5)。★同時に走らせる演出の上限 `FX_LIMIT` は 8 である。

  配りの段は 380 + 4 × 110 = **820ms** になる(番人 85b-17 が測る)。

- ★着地点の本物は、飛んできた面が着いた瞬間に見せる(それまで隠す)。

## 3. ★★★84b の出口の穴を1つ直した —— 累計時間を操作をまたいで持ち越していた

★スクリーンショットで呪文の連鎖を見たら、<b>1段目から「残り3段は演出を省いた」が出ていた</b>。

★原因は 84b の `stepPump` である。累計時間(`stepSpent`)を戻すのは「キューが空の `stepPump`」だけで、
★★<b>最終状態を待たずに終える出口(後ろに誰も居ないとき)では戻していなかった</b>。
<b>前の操作で使った時間が次の操作へ持ち越され、次の操作の上限(裁定364)が先に尽きていた</b>。

```js
if (item.final && stepQueue.length === 0) {
    stepPlaying = false;
    stepSpent = 0;          // ★85b で足した
    stepSyncScreen();
    return;
}
```

★★<b>84b の番人は毎回 `stepDropAll` で戻してから測っていた</b>ので、この持ち越しを見ていなかった。
★85b で段が長くなって表に出た(1操作 = 詠唱 1.2秒 + 着弾 1.3秒 × n)。★番人 85b-19 と軸17 を置いた。

> ★★<b>番人が毎回状態を初期化してから測ると、状態の持ち越しという種類の不具合を原理的に見ない。</b>
> ★<b>「続けて2回やる」番人が1本要る</b>(落とし穴に足した)。

★これは裁定364 の<b>意味を変えない</b>(「この操作でここまでに使った再生時間」の実装を、書いてあるとおりにした)ので、採番していない。

### 4-1. ★★★番人の穴を2つ、壊し検証の軸を立てる前に塞いだ

★軸を考えていて、<b>抑止の行を通る入力を番人が作っていない</b>ことに2つ気づいた。

   <b>出現の抑止の行を1度も通らない</b>。→ 飛行の無い召喚(山札から2体を同時に出す)を 85b-13 に足した。
2. ★<b>ドローの「手札への出現」の抑止</b>。85b-16 は差分の<b>飛行</b>だけを数えていたが、

> ★85b-11 が<b>対照</b>(出来事が無ければ差分の飛行が1本出る)を先に測っているのは、そのためである。

### 4-2. ★判定を2箇所に置くと、壊し検証が当たらない
