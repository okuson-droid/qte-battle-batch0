## 1. 設計

**骨格は手動モードと同じ「中央列(可変)+ 右列(400px)」。**
右列にフェイズ操作・選択の問いかけ・ログ(残り高さへ flex で伸びる)。
中央列は 相手の帯 → 相手ミニオン → 自分ミニオン → 自分の帯 → 手札。

- **★要素の id は1つも変えていない。** battle.js の描画は数字を id で書き込むだけなので、
  置き場所の組み替えを JS はほぼ知らない(42 の「状態クラス名を変えない」と同じ手法)。
- **チップ化**: 相手情報の複数行の文字列(38 まで)を1行のチップ列に。
  墓地・消滅・マナは従来どおりクリックで一覧モーダル。
- **手札は重ねて並べる**(`margin-left: -34px`・ホバーで持ち上がる)。
  8枚でも中央列(約845px)に収まる。商業作品の扇の簡易版。
- **禁忌は既定で畳む**(帯の「禁忌 n」チップで開閉)。開くと手札の**上に重なり**、
  レイアウトの高さを消費しない。★支払い中(`tabooPay`)は閉じる操作をしても閉じない
  (どの禁忌を使おうとしているか見えないままマナを選ばせない)。
- 禁忌の帯は**完全不透明**で、下方向へ 10px はみ出す(手札の選択リングの
  box-shadow が要素の外へ光るため、ぴったり重ねると下端から光だけ漏れる)。

## 2. 検証

- **★43-1 が本題の番人**: 両席ミニオン6・手札8・マナ8・禁忌2 の「盛った盤面」で
  `scrollHeight <= 800`。空の盤面で測ると無条件に通ってしまう。
- autoPage のビューポートを 1280×800 の実寸に落とした。**収まっていなければ
  42 の実マウス項目が押せず落ちる**ので、ビューポート自体が第2の番人になる。
- ★43-4 は最初「帯が開いている」だけを見ており、自動オープンのガードを外しても
  素通りした。**「閉じる操作を実際に試みて、閉じないこと」を測る形に直した**。
  番人は壊し方から逆算して書くこと(検証の教訓として残す)。
- わざと壊す確認3通り(重なり削除 / ガード削除 / 帯を static に)すべて意図どおり落ちた。
- ★既知フレーク: デッキメーカーの「組みかけは黙って捨てられない」等2項目が
  高負荷時に1回落ちた(構築ループのクリック取りこぼし。main 7/40 で判別できる)。
  再現率 1/4。落ちたらまず再実行すること。

## 3. 確認手順(マスターの手元)

1. Eclipse refresh(F5)→ スーパーリロード(css v=43 / battle.js v=16)。
2. **1280×800 程度のウィンドウで縦スクロールが出ない**こと。
3. 相手情報がチップ列になり、墓地・消滅・マナのクリックで一覧が開くこと。
4. 「禁忌 n」チップで帯が開閉し、支払い中は閉じられないこと。
5. 手札が重なって並び、ホバーで持ち上がること。
6. ログが右列で伸びること。フェイズ操作が右列上部にあること。
