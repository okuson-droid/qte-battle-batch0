# Batch 13b 設計解説 — 土文明カード登録(28枚)＋豊穣の地霊主の数え直し方式化

本バッチは、Batch 13a で用意した土文明の土台（表向きマナ配置・ON_COMBAT_KILL・ON_EQUIP・
守護盾の肩代わり・絶対神ガイアの攻撃制限）の上に、土文明 28 枚の効果を実際に登録する作業である。
あわせて、豊穣の地霊主（L012）の「2 回目のマナ配置」判定を、相手ターン中の配置も正しく数える
方式へ改めた。これで水・火・闇・光・風・土の全 6 文明が実装済みとなる。

---

## ⚡ 結論チートシート

- **豊穣の地霊主は「数え直し方式」に変わった。** マナ配置カウンタは自ターン開始時にリセットするのを
  やめ、配置のたびに現在のターン番号と照合して、ターンが変わっていれば 0 から数え直す。これにより
  相手ターン中の配置（地砕きの突撃兵の破壊時マナ加速など）も、そのターンの回数として正しく数える。
- **土 28 枚の登録先は「効果の置き場所」で決まる。** スペル＝`spellEffects`、ミニオン/ウェポンの
  誘発＝`register(id, TriggerType, …)`、対象選択＝`targetSpecs`、特殊召喚＝`specialSummons`、
  リーダー起動＝`leaderAbilities`、動的ステータス＝`StatCalculator`、ウェポン攻撃時＝
  `GameService.leaderAttack` の switch。すべて `registerEarthCards()` に集約した（StatCalculator と
  GameService と DeckFactory を除く）。
- **手札をマナに置くときは `placeCardInManaFaceUp(room, owner, cardId)` を直に呼ぶ。**
  対象に選ばれた手札カードは検証時点で手札から除去済みで渡るため、インデックス版の
  `placeHandCardIntoManaFaceUp` を使うと二重除去になる。
- **見落としやすい配線を 2 か所直した。** 土文明を「実装済み」として認識させるため、
  `DeckValidator.IMPLEMENTED` と `LobbyController.selectableLeaders()` に `EARTH` を足した。
  これを忘れると土デッキが検証で弾かれ、土リーダーが選択画面に出ない。
- **バニラ 3 枚と 13a 済み 2 枚は登録不要。** 不動の岩石竜・百獣の王ベヒーモス・ゴーレム・ウォールは
  キーワードのみ。豊穣の地霊主と大地の守護盾は 13a で実装済み。

## ★★★★ 1. 豊穣の地霊主の「数え直し方式」

### 1-1. 何が問題だったか

豊穣の地霊主（L012）は「マナにカードが置かれたとき、そのターン中それが 2 回目なら 1 ドロー」という
常在トリガーである。Batch 13a では配置回数を `PlayerState.cardsPutToManaThisTurn` に持ち、
`startTurnReset()`（自分のターン開始時）で 0 に戻していた。

この方式には穴がある。マナ配置は自分のターンだけで起きるとは限らない。土文明には
**地砕きの突撃兵（0155）の「破壊されたとき山札の上から 1 枚を表向きでマナに置く」**があり、これは
相手のターン中に自分のミニオンが破壊されて発火しうる。自ターン開始時リセットだと、相手ターン中の
配置が「前回の自分のターンの残り回数」に積み上がってしまい、2 回目の判定がずれる。

### 1-2. ★解決 — カウンタに「どのターンの計数か」を持たせる

カウンタ本体に加えて、そのカウンタが記録しているターン番号 `manaPlacedCountTurn` を持たせた。
`GameState.turnNumber` はゲーム全体で単調増加する（両プレイヤー通しでターン開始のたびに +1）。
配置のたびに、この番号とカウンタの記録が食い違えば「別のターンの配置」とみなし、カウンタを 0 に
戻してから数える。実体は `PlayerState.recordManaPlacement(int currentTurn)` の 1 メソッドに閉じた。

```java
// PlayerState
private int cardsPutToManaThisTurn = 0;
private int manaPlacedCountTurn = -1;   // -1 はどのターンとも一致しない番兵

public int recordManaPlacement(int currentTurn) {
    if (manaPlacedCountTurn != currentTurn) {   // ターンが変わった → 数え直す
        manaPlacedCountTurn = currentTurn;
        cardsPutToManaThisTurn = 0;
    }
    cardsPutToManaThisTurn++;
    return cardsPutToManaThisTurn;
}
```

配置の唯一の入口 `GameActions.placeCardInManaFaceUp` は、これを現在のターン番号とともに呼ぶ。

```java
owner.recordManaPlacement(room.getGameState().getTurnNumber());
```

`startTurnReset()` からは `cardsPutToManaThisTurn = 0;` を削除した（開始時リセットに依存しない
設計に一本化するため）。仮に開始時リセットが残っていても数え直しロジックが上書きするので害はないが、
「配置のたびにターン照合して数え直す」という一貫した意味を保つために外している。

`fireManaPlaced` の判定は `== 2` のまま変えていない。2 回目の配置後にカウンタが 2 になり、
そこで 1 ドローが正しく発火する。

## ★★★ 2. 28 枚の登録先の地図

土 28 枚を「どこに何を書いたか」で並べる。★は理解の要点。

### 2-1. リーダー起動能力（`leaderAbilities`）

- **大地の巨頭（L011）** — コスト 4 で手札 1 枚を表向きマナに置く。`LeaderAbilitySpec.of(4, …)`。
  手札の選択は `TargetSpec` の `HAND, SELF, 1`。★選ばれた手札は検証時点で除去済みで渡るため、
  `handCardIds()` を `placeCardInManaFaceUp(room, owner, cardId)` に渡すだけでよい（後述 2-6）。
- **豊穣の地霊主（L012）** — 1 節で述べたとおり `fireManaPlaced` に実装済み。登録不要。

### 2-2. 召喚時（`register(id, ON_SUMMON, …)`）

| ID | カード | 効果 |
|----|--------|------|
| 0137 | 大地の精霊グラン | 山札の上 1 枚を表向きマナ（`placeTopOfDeckInManaFaceUp`） |
| 0156 | 苗木植えの精霊 | 手札 1 枚（選択）を表向きマナ。`targetSpecs` ＋ ON_SUMMON |
| 0138 | 創世神ガイア | 自身以外の、お互いの場のミニオンをすべて破壊 |
| 0145 | 天変地異のタイタン | 相手の場すべてに 7 ダメージ＋2 ドロー |
| 0153 | アースクエイクジャイアント | 相手の【守護】ミニオンをすべて破壊（GUARD で filter） |
| 0152 | 安らぎのガーディアン | リーダーを 2 回復（＋ターンエンド時に 4 回復） |

★全体系（0138・0145・0153・後述の大地震 0148）は `List.of(ctx.owner(), ctx.opponent())` で両者の場を
回し、`List.copyOf(side.getMinionZone())` のコピーに対して回す。破壊はコレクションを変更するため、
コピーを回さないと `ConcurrentModificationException` になる。創世神ガイアは `m != ctx.source()` で
自身を除外する（`source()` は召喚されたそのインスタンスで、場のリストと同一オブジェクトのため参照比較で足りる）。

### 2-3. その他トリガー

- **連撃の巨岩（0017）** — 2 回攻撃は `StatCalculator.maxAttacks`（後述 2-7）。ターンエンド時に
  自分を手札に戻すのは `register(0017, ON_TURN_END, ctx -> bounceToHand(…, ctx.source()))`。
  ★ON_TURN_END の発火（`GameService` の掃除前）では `ctx.source()` がそのミニオンになる。
- **疾風怒濤のベヒーモス（0144）** — ターンエンド時バウンスのみ（攻撃回数の上書きは持たない）。
- **タイタン・ウォリアー（0140）** — `ON_COMBAT_KILL`（13a 新設）。戦闘で相手ミニオンを撃破した側に
  発火し、相手リーダーに 4 ダメージ。破壊された側に発火する `ON_DESTROYED_BY_COMBAT` とは向きが逆。
- **不動の絶対神ガイア（0150）** — リーダーを攻撃できない制約は 13a の `RuleGuards`。攻撃時の
  相手リーダー 4 ダメージは `register(0150, ON_ATTACK, …)`。
- **地砕きの突撃兵（0155）** — `ON_ATTACK`（マナ回収）と `ON_DESTROYED`（山札からマナ加速）の
  2 つ。★攻撃時マナ回収の「1 枚選び」は近似実装（後述 2-8）。

### 2-4. ウェポン

- **ガイア・ハンマー（0142）** — `register(0142, ON_EQUIP, …)`（13a 新設のトリガー）。装備時に山札の
  上 1 枚を表向きマナ。★召喚時（ON_SUMMON）ではなく装備時であることが発注者確認済みの裁定。
- **地響きの槌（0009）** — 攻撃時に相手ミニオン全体へ 2 ダメージ。既存のウェポン攻撃時効果と同じく
  `GameService.leaderAttack` のウェポン switch に直書きした（Registry ではない）。
- **大地の守護盾（0146）** — 肩代わりは 13a 実装済み。登録不要。ウェポンとして装備できればよい。

### 2-5. スペル（`spellEffects`）

| ID | カード | 効果 |
|----|--------|------|
| 0139 | 落石の罠 | 相手ミニオン 1 体（`targetSpecs`）に 5 ダメージ |
| 0148 | 大地震 | お互いのコスト 3 以下のミニオンをすべて破壊（**印刷コスト** `master.cost()` で判定） |
| 0149 | 大地の開眼 | 1 ドロー。マナ 7 枚以上ならさらに 1 ドロー |
| 0151 | ガイア・リソース | 山札からマナ加速。【還元】 |
| 0157 | 豊穣の祈り | 山札からマナ加速＋2 ドロー |
| 0158 | 大地の恵み | 山札からマナ加速 |
| 0015 | 地脈の覚醒 | 解決時の固有処理なし（★空登録）。動的コストは StatCalculator、マナ加速は【還元】 |

★【還元】（地脈の覚醒・ガイア・リソース）の「唱えた後にマナへ置く」処理は GameActions 側の共通処理が
担う。`spellEffects` には解決時の固有効果だけを書く。地脈の覚醒は固有効果が無いが、
`isSpellImplemented` を true にしてプレイ可能にするため、空のラムダを登録している。

★大地震の「コスト 3 以下」は effectiveCost（動的コスト）ではなく印刷コスト（`master.cost()`）で
判定する。`cost()` は `Integer`（リーダーは null）だが、対象は場のミニオンに限るため実質 non-null。
念のため `c != null && c <= 3` で null 安全にしている。

### 2-6. ★手札 → マナは `placeCardInManaFaceUp` を直に呼ぶ

苗木植えの精霊・大地の巨頭は「手札 1 枚を表向きでマナに置く」。ここで陥りやすい罠がある。

`ResolvedTargets` の規約では、**対象に選ばれた手札カードは検証時点ですでに手札から除去された状態で
効果に渡る**（`handCardIds()` の Javadoc）。行き先（墓地・山札の下・マナなど）は効果が決める設計だからだ。
したがって、インデックスを取って手札から抜く `placeHandCardIntoManaFaceUp(room, owner, handIndex)` を
使うと、**すでに抜かれた手札をもう一度抜こうとして二重除去になる**。

正しくは、除去済みで渡る `cardId` を、山札からのマナ加速と同じ最終入口 `placeCardInManaFaceUp(room,
owner, cardId)` に渡すだけでよい。

```java
ctx.targets().get(0).handCardIds().forEach(
        id -> ctx.actions().placeCardInManaFaceUp(ctx.room(), ctx.owner(), id));
```

（`placeHandCardIntoManaFaceUp` 自体は 13a で用意したが、今回の対象選択方式では使わない。将来、
割り込み選択の途中でインデックスが渡ってくる経路が必要になったときのために残してある。）

### 2-7. 動的ステータス（`StatCalculator`）

| ID | カード | 実装箇所 | 内容 |
|----|--------|----------|------|
| 0008 | 無尽蔵の巨神 | `effectiveAttack` | 攻撃力＝自分の手札枚数（基礎 0 ＋ 手札枚数）。知識の守護者（0037）と同型 |
| 0143 | 大地の狂戦士 | `effectiveCost` | マナ 7 枚以上でコスト 1 |
| 0015 | 地脈の覚醒 | `effectiveCost` | マナ 7 枚以上でコスト 2 |
| 0017 | 連撃の巨岩 | `maxAttacks` | 攻撃回数 +1（サイクロン・フェンサー 0133 と同型） |

★土の動的コストは、他文明の「-1 する」減算型と違い「条件を満たすと固定値になる」セット型である。
`cost = 1` / `cost = 2` を代入する。マナ枚数は `owner.getManaZone().size()`（表向き・裏向きを問わない
マナゾーンの総枚数。土は表向きしか作らないため実質すべて表向き）。

### 2-8. ★地砕きの突撃兵の攻撃時マナ回収は自動選択で近似（要確認事項）

地砕きの突撃兵（0155）の攻撃時効果は「自分のマナから 1 枚**選び**手札に戻す」である。だが現状、
ON_ATTACK のタイミングで対象を選ばせる仕組みは存在しない（対象選択はプレイ時／起動時にしか
挟めない）。そこで、12b で用意した `returnFaceUpManaToHand`（最後に置かれた表向きマナを 1 枚戻す）を
使い、**自動選択で近似**した。死霊の収鎌（0089）が墓地からの回収を AutoChoice で自動決定しているのと
同じ割り切りである。

厳密な「1 枚選び」を実現するには、攻撃時の割り込み選択（a9 系）が必要になる。それが入るまでは自動
選択のままとする。**この近似が許容できるかは発注者確認事項**として下の理解確認に挙げる。

### 2-9. ★見落としやすい 2 つの配線 — DeckValidator と LobbyController

効果を登録しただけでは土デッキは遊べない。土文明を「実装済み」として認識させる 2 か所がある。

- `DeckValidator.IMPLEMENTED`（実装済み文明の集合）に `Civilization.EARTH` を追加。ここに無いと、
  土リーダー・土カードを含むデッキが検証で `IllegalArgumentException` になる。
- `LobbyController.selectableLeaders()`（選択画面に出すリーダーの一覧）に `Civilization.EARTH` を追加。
  ここに無いと、土リーダー（大地の巨頭・豊穣の地霊主）が選択肢に現れない。

なお `selectableLeaders()` は現在 WATER / FIRE / DARK / LIGHT / EARTH の 5 文明を列挙しており、
**WIND は含まれていない**。これは風文明がまだ選択解禁の段階に無いためと解釈しているが、風の
リーダー選択を解禁するかどうかは風バッチ側の判断に委ねる（本バッチでは触れていない）。

## ✅ 動作確認手順

前提: `./mvnw spring-boot:run` で起動し、`http://localhost:8080/`（本番は Render）を 2 タブで開く。
リーダー選択で **大地の巨頭** または **豊穣の地霊主** を選び、土スターターで対戦する。

   突撃兵を相手ターン中に破壊させて山札からマナ配置が起きても、その回数が正しく数え直されること

3. **動的ステータス** — 無尽蔵の巨神（0008）を出し、手札を増減させると攻撃力が手札枚数に連動する

4. **全体除去** — 創世神ガイア（0138）を召喚し、自身以外の全ミニオンが消えることを確認。マナ 10 枚

   アースクエイクジャイアント（0153）で相手の守護だけが消えることを確認。
5. **ウェポン** — ガイア・ハンマー（0142）を装備した瞬間に山札からマナが 1 枚増えることを確認。
   地響きの槌（0009）でリーダー攻撃すると相手ミニオン全体に 2 ダメージが入ることを確認。大地の守護盾
   （0146）を装備した状態でリーダーが攻撃されると、盾が割れてダメージが通らないことを確認。
6. **撃破・攻撃トリガー** — タイタン・ウォリアー（0140）で相手ミニオンを戦闘破壊すると相手リーダーに
   4 ダメージが入ることを確認。絶対神ガイア（0150）は相手リーダーを攻撃対象に選べず、攻撃時に相手
   リーダーへ 4 ダメージが入ることを確認。

## ✅ 理解確認

<details>
<summary>Q1. 豊穣の地霊主のカウンタを「自ターン開始時リセット」から「数え直し」に変えたのはなぜか。</summary>

マナ配置は自分のターンだけで起きるとは限らないから。地砕きの突撃兵の破壊時マナ加速は相手ターン中に
発火しうる。開始時リセットだと、相手ターン中の配置が前回の自分のターンの残り回数に積み上がって
2 回目判定がずれる。配置のたびにターン番号を照合して数え直せば、どのターンの配置でもそのターンの
回数として正しく数えられる。
</details>

<details>
<summary>Q2. 手札をマナに置くのに placeHandCardIntoManaFaceUp(handIndex) を使ってはいけないのはなぜか。</summary>

対象に選ばれた手札カードは検証時点ですでに手札から除去された状態で効果に渡るため。インデックス版は
内部でもう一度手札から抜こうとするので二重除去になる。除去済みで渡る cardId を
placeCardInManaFaceUp(room, owner, cardId) に渡すのが正しい。
</details>

<details>
<summary>Q3. DeckValidator と LobbyController に EARTH を足さないと何が起きるか。</summary>

DeckValidator.IMPLEMENTED に無いと、土カードを含むデッキが「未実装文明」として検証で弾かれる。
LobbyController.selectableLeaders() に無いと、土リーダーが選択画面に現れず、そもそも土文明を選べない。
効果を登録しただけでは遊べず、この 2 つの配線が必要になる。
</details>

<details>
<summary>Q4. 地砕きの突撃兵の攻撃時マナ回収は仕様どおりか。確認したい点は何か。</summary>

仕様は「自分のマナから 1 枚**選び**手札に戻す」だが、現状 ON_ATTACK で対象を選ばせる仕組みが無いため、
最後に置かれた表向きマナを自動で 1 枚戻す形（returnFaceUpManaToHand）で近似している。死霊の収鎌の
AutoChoice と同じ割り切り。**この自動選択で許容できるか、それとも割り込み選択の導入まで待つべきか**が
発注者確認事項である。
</details>
