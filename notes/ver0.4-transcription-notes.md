# Ver.0.4 転記ノート — カード52枚＋ルール変更1件

本ノートは、マスターから提示された Ver.0.4 バランス調整資料を台帳(`qte-cards.json`、
プロジェクトルート・resources の両方、169枚)へ転記した記録である。**このバッチはデータ更新のみ**
であり、Java コードには一切手を入れていない。効果の実装(15a〜15d)は次バッチ以降となる。

台帳の各カードには、通常の効果テキストに加えて `notes` フィールドに `Ver.0.4:` から始まる
実装注記を残した。15a 以降の作業ではまずカードの `notes` を読むこと。

## ⚡ 結論チートシート

- **52枚すべて転記完了。台帳2箇所(プロジェクトルート・resources)は内容一致、機械チェック全通過。**
- **ルール変更が1件ある。「ウェポンは攻撃したらそのターンの終わりに破壊される(禁忌の場合消滅する)」。**
  これはカードではなく総則の変更であり、`qte-cards.json` には反映されていない。15a で実装する。
- **新しい仕組みが4つ必要になる(15aの主題)。**
  1. ウェポンの「攻撃後、ターン終了時に破壊」という寿命の概念(耐久値ではなく1回制限)
  2. ミニオンゾーン上限のプレイヤーごとの動的化(大地の巨頭が自分だけ8体)
  3. ウェポンが「自分のミニオンの攻撃/場に出た」に反応する新しい発火口(レーヴァテイン・禁忌の冥魔剣)
  4. リーダー回復の「量」と「発生源の文明」を数える計数(ヴォルカニクスレヴォ)
- **13cで実装したばかりの2つの登録を削除する。** 大地の巨頭(L011)の起動能力(leaderAbilities登録)、
  地脈の覚醒(0015)のStatCalculatorの動的コスト分岐。理由は下記参照。
- **確認が必要だった2枚は解決済み。** 剛火の将(L004)は資料との数値の食い違いを無視して-1のまま確定、
  ストーム・カイザー(0120)は【特殊召喚】キーワードを外す読みで確定。

## ★★★★ 1. ルール変更: ウェポンの寿命

> ウェポンは攻撃したらそのターンの終わりに破壊される(禁忌の場合消滅する)

**確定した解釈(発注者確認済み)**:
- 「攻撃した」= そのウェポンを装備した**リーダーが攻撃した**時のみ(ミニオンの攻撃では発動しない)。
- 破壊されるのは**自分のターン終了時**。
- 攻撃後に別のウェポンへ**付け替えた**場合、新しいウェポンは(攻撃していないため)壊れない。

**実装方針(15a)**:
- ウェポンに「このターン攻撃したか」のフラグが要る。`PlayerState` あたりに
  `weaponAttackedThisTurn`(boolean)を追加し、`GameService.leaderAttack` のウェポン攻撃経路で立てる。
- ターン終了処理(`startTurnReset` 相当、ないし `finishEndTurnCleanup`)で、フラグが立っていれば
  `GameActions.destroyOwnWeapon` を呼んで破壊する。フラグ自体はターンをまたいでリセットする。
- **消滅(禁忌の場合)は既存の `sendToTrashOrRestore` がそのまま処理する。** 禁忌カードは
  `fromTaboo` フラグにより自動的に `lostZone` へ送られるため、新しい消滅処理は不要。
  `destroyOwnWeapon` を呼びさえすれば消滅は自動でついてくる。

## ★★★★ 2. 新しい仕組みが必要な4枚

### 2-1. 大地の巨頭(QTE-L011): ミニオンゾーン上限の動的化

新テキスト: 「自分のミニオンは6体ではなく8体まで場に出せるようになる。」(常在効果、起動能力は廃止)

`PlayerState.MAX_MINIONS = 6` が定数で、`GameService` の4箇所・`PlayerState.isMinionZoneFull()`・
`CardEffectRegistry`(TargetSpec.upToの上限指定)から参照されている。プレイヤーごとの上限に
変えるには、この4+α箇所を横断的に改修する必要がある。設計方針の候補:
- `PlayerState` にインスタンスフィールド `int minionZoneLimit = 6;` を持たせ、リーダーが
  大地の巨頭のときだけ8で初期化する(ゲーム開始時、リーダー確定のタイミングで設定)。
- 各所の `MAX_MINIONS` 参照を `player.getMinionZoneLimit()` に置き換える。

**13cで実装した起動能力(手札1枚をマナに置く)は削除する。** `leaderAbilities.put("QTE-L011", ...)` の
登録一式(CardEffectRegistry)を消すこと。今のまま残すと、存在しないはずの能力ボタンが出てしまう。

### 2-2. ウェポンが「自分のミニオン」に反応する新しい発火口

- **魔剣レーヴァテイン(QTE-0061)**: 「自分のミニオンが攻撃した時、自分のリーダーに1ダメージ。」
  攻撃宣言ごとに1ダメージ(2回攻撃なら2回、発注者確認済み)。
- **禁忌の冥魔剣(QTE-0073)**: 「自分のミニオンが場に出たとき相手のリーダーに1ダメージ」。
  「場に出たとき」= ON_ENTER(蘇生・特殊召喚でも発動、発注者確認済み)。

どちらも**ウェポンを装備している間、自分のミニオンのイベントを監視する**必要がある。
既存のウェポンの発火口は「装備時(ON_EQUIP)」と「リーダー攻撃時(leaderAttackのswitch)」の2つのみで、
「自分のミニオンの攻撃/登場」を拾う経路が無い。豊穣の地霊主の`fireManaPlaced`(常在型トリガーが
装備品と無関係にイベントを監視する)と同じ考え方で、新しい発火口を用意する必要がある。実装候補:
- `CardEffectRegistry` に「装備中のウェポンを持つプレイヤーの、ミニオンの攻撃/登場」を監視する
  メソッドを新設し、`GameService` の ON_ATTACK 発火箇所・ON_ENTER 相当の箇所から呼ぶ。
  ウェポンの効果なので `TriggerType` に新種を増やすのではなく、既存の
  ON_ATTACK/ON_ENTER 発火の隣で「装備品のIDをチェックして処理する」形(既存のウェポン攻撃時
  switchと同じ発想)が既存構造との整合性が高い。

### 2-3. 鳳凰神ヴォルカニクスレヴォ(QTE-0058): 回復量の計数

新テキスト: 「このターン5以上火文明のカードで回復したときこのカードを手札から0コストとして出せる。」

判定基準は「回復した**回数**」ではなく「累計**回復量**」、かつ「**火文明のカードの効果による
リーダー回復**」のみが対象(発注者確認済み)。既存の `PlayerState.healedCountThisTurn` は
回数のカウンタであり、量も発生源の文明も持たない。`GameActions.healLeader` に発生源のカード情報を
渡す引数を追加する必要がある(`GameActions.damageLeader` には既に発生源引数があるため、それに揃える形)。
文明ごとの累計回復量を持つフィールド(あるいは発生源カードの文明を都度参照して加算する処理)が要る。

## ★★★ 3. 13cの実装を削除する2件

- **大地の巨頭(L011)の起動能力**(上記2-1)。新仕様は常在効果のみで起動能力を持たない。
- **地脈の覚醒(0015)の動的コスト**。新テキストは「コスト2【還元】」で、マナ枚数条件そのものが
  撤廃され基礎コストが固定2になった。`StatCalculator.effectiveCost` の
  `if ("QTE-0015"...マナ7枚以上...) cost = 2;` という分岐は、台帳の基礎コストを2にした時点で
  常に真になる死んだコードになるため削除する。効果自体(【還元】のみ、固有解決処理なし)は
  13bと同じ空登録のまま残す。

対して **大地の狂戦士(QTE-0143)の動的コストは変更なしで存続する。** マナ7枚以上でコスト1という
条件は変わらず、【還元】キーワードが追加されるだけである。

## ✅ 動作確認手順(転記の確認方法)

このバッチはコード変更を伴わないため、対戦での動作確認は次バッチ(15a)以降になる。
今回確認すべきは台帳の値そのものが正しいかであり、次の方法で確認できる。

1. デッキビルダー(`/deck-builder`)を開き、各文明のカードのコスト・スタッツ・キーワード表示が
   本ノート5章の一覧と一致することを確認する。
2. カード一覧ページ(`/cards`)でも同様に、テキストが更新されていることを確認する。
3. `git diff` で `qte-cards.json` の変更差分を見て、意図しない変更が混ざっていないか確認する。
