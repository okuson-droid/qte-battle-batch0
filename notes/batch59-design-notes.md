## 2. 構造の手当て3件

### 2-1. 「ターンに n 回まで」の器を1本にした(裁定264 + 276)

マスターは **264 と 276 を「同じ規則の2つの現れ方」として揃えて裁定した。**
したがって実装も1本にしてある(裁定163)。

```java
// PlayerState
private final Map<String, Integer> turnLimitedUses = new HashMap<>();
private int turnLimitedUsesTurn = -1;

public boolean tryUseTurnLimited(String key, int currentTurn, int maxPerTurn)
```

Batch 58 が《地脈の覚醒》専用に作った `tryUseLeylineAwakening(int)` を置き換えた形である。

★**ターン番号の刻印を1つしか持たない。**ターン番号は両プレイヤーで共有された1本の数であり、
「今が何ターン目か」は制限の鍵ごとに違わない。
ターンが変わった最初の問い合わせで表ごと捨てれば数え直しになる。

★**`startTurnReset()` に頼らない**(58 からの継続)。あれが走るのはターンプレイヤーだけであり、
《禁忌の冥魔剣》が相手のターンに発動しないのは今のカードプールの偶然にすぎない。
規則をその偶然に寄りかからせない。

★**判定と記録は1つのメソッドの中にある。**分けると「判定したが記録し忘れる」経路が生まれ、
どちらのカードも同じターンに2回目を撃てるので必ず踏む(`qte-pitfalls.md` の Batch 58 節)。

### 2-2. 「相手が引いたとき」の発火口を新設した(裁定270)

`TriggerType.ON_OPPONENT_DRAW` と `CardEffectRegistry.fireOpponentDrew` を足し、
`GameActions.drawCards`(= 山札から手札へカードが動く唯一の場所)から焚く。

★**このトリガーだけが持つ2つの性質。**

1. **相手の手番中に発火する。**他のトリガーはすべて、反応するミニオンの持ち主が
   手番を持っているか、少なくとも盤面の出来事に紐づいていた。
   これは「相手がターン開始時に引いた」だけで発火する ——
   **1ターンに最低1回、必ず起きる**ということである。
2. **誘発によるドローでは発火しない**(6-1 で詳述)。

★**カードIDは `GameActions` に1つも書いていない。**発火口を通す形にしたので、
「誰が反応するか」は登録の側にある(裁定163)。
`StatCalculator` にあった《英知の水晶》のコスト軽減は削除し、定数も
`IMPLEMENTED_CARDS` も落とした —— 宣言から登録へ移った1枚である。

### 2-3. ミカエルの置換する層を1段下げた(裁定272)

| | 旧 | 新 |
|---|---|---|
| 本文 | 「【守護】戦闘では破壊されない(ダメージは受ける)」 | 「【守護】戦闘時ダメージを受けない」 |
| 置換する層 | **破壊**(`RuleGuards.isDestructionPrevented`) | **ダメージ**(`RuleGuards.preventsCombatDamage`) |
| HPの挙動 | 削れる。0以下のまま場に残る | **削れない** |
| その後 | 次の効果ダメージ・効果破壊で落ちる | 何度戦闘しても満身のまま |

★**受けるダメージを0にするのではなく、適用そのものを行わない。**
マスター裁定272 は「【守護】被ダメージ誘発(《獄門の裁定者》)は発動しなくなる」と決めた。
量を0にして先へ進めると、適用側の `amount <= 0` で止まる作りに**依存する**ことになる。
`GameActions.dealCombatDamage` の入口で止めれば、誘発が焚かれないことが構造で保証される。

★**効果ダメージは通る。**本文が「戦闘時」と限定しているためである(裁定211)。
壊し検証はこの両側を別々のケースで押さえている(ケース19・20)。

## 3. カードごとの読みどころ

### 3-1. ガイル・フォックス —— 閾値が経路で1違う(裁定262)

本文は「このターン中にカードを3枚以上使用しているなら【潜伏】」だが、
使用カウンタ(`cardsUsedThisTurn`)は**解決中にはまだ自身を数えていない**(裁定1)。

- 自身の**召喚**で登場した場合、このカードは今まさに使用されている最中なので、
  カウンタが **2** のとき本文の言う「3枚以上」を満たす。
- **効果**で場に出た場合、このカードは使用されていないので、素直に **3** 以上を求める。

そこで ON_SUMMON(閾値2)と ON_ENTER(閾値3)の**2つに登録した**。
通常召喚では両方が通るが、**【潜伏】の付与は冪等**なので二重にならない。

★**常在の再評価ではない。**印が消えたことで「毎瞬間に評価し直す常在」とも読めたが、
マスターは「登場時に判定し、**永続的に**持つ」と決めた。条件を失っても手放さない。

### 3-2. 悪夢 —— 判定を `fire()` の入口に置いた(裁定265)

【召喚時】(ON_SUMMON)を焚く場所は通常召喚・進化召喚・特殊召喚・禁忌からの使用と複数ある。
呼び出し側で止めると**足し忘れた経路だけが素通りする**(裁定163)ので、
`CardEffectRegistry.fire()` —— ON_SUMMON が必ず通る1点 —— に置いた。

★**この判定を【知識】の共通処理より前に置いてある。**順序に意味は無い
(【知識】は ON_ENTER でしか動かないので ON_SUMMON の判定とは元から交わらない)が、
**2つを分けているものが「誘発の種類」ただ1つである**ことを構造で示すためである。
後ろに置くと「順序のおかげで守られている」ようにも読め、壊し検証でこの軸を狙えなくなる。

★**本文の2行目はサブフェイズの条件に掛かっていない。**したがって
コスト-4(サブフェイズのときだけ)とは独立に張られる ——
**メインフェイズに撃つと「【召喚時】が死ぬだけで何の見返りも無い」**。
本文どおりの読みであり、実装で和らげない(裁定211)。

★**対象の選択は止まらない。**対象は使用を宣言した時点で選び終えており、効果だけが発動しない。
《地脈の覚醒》の2枚目(裁定276)と同じ姿である。

### 3-3. 神風の大号令 —— 「いるだけ」を対象指定で表せない(裁定269)

破壊するミニオンは本人が選ぶ(裁定192: 盤面に残るものを決める選択)。
だが要求は `upTo`(0〜2体)にせざるを得なかった ——
`Requirement` の `count` は**登録時に固定される値**であり、
「min(2, 場のミニオン数)体ちょうど」という**盤面に依存する要求数**を
今の対象指定システムは表現できないためである。

★結果として、**2体居るのに1体だけ・0体だけ選ぶこともできてしまう。**
ただし破壊した数がそのまま強化量なので、少なく選ぶのは自分が損をするだけである
(0体を選べば実質「コスト3でマナを1枚増やすだけのカード」になる)。
**この穴を塞ぐべきかは裁定を仰いでいる(裁定277)。**

★**強化を受けるのは破壊した「後」に場に残っているミニオンである。**本文の順序どおりであり、
2体しか居ない場で2体壊すと強化先が居ない。

★**強化の期限(このターン)は動かしていない。**旧本文にも新本文にも期限は書かれておらず、
Ver.0.4 の時点で「このターン」と決めてある。裁定269 が動かした軸ではないので据え置いた
(《突風の祝福》の体力+2 が恒久なのと非対称のままである)。

### 3-4. マナを貪る怨霊 —— 選ばせない(裁定273)

本文に「選び」が無いので選ばせない(裁定211)。**墓地の古い順**に闇文明のカードを2枚取る ——
墓地は置かれた順のリストであり、「先に死んだものから土に還る」が最も素直な並びである。

旧本文が持っていた使用条件(表向きのマナが1枚以上)は削除した。
「あるだけ置く」形なので0枚でも使用できる —— **《神風の大号令》の裁定269(b) に揃えた**。

### 3-5. 地響きの槌 —— 破壊の数え方(裁定274)

「この効果で破壊したミニオンの数」を、**ダメージの前後で場から消えた数**ではなく
**そのダメージ適用で場を離れた数**として数える。
前後の差で数えると、ダメージとは無関係に場を離れたミニオン
(被ダメージ誘発《獄門の裁定者》の巻き添えなど)まで数に入ってしまう。

対象はダメージを与え始める前の盤面で確定する(解決中に場へ出たミニオンは巻き込まない)。

### 3-6. 地脈の覚醒の2枚目 —— 【還元】もしない(裁定276)

Batch 58 は「【還元】はキーワードであって効果ではない」と読んで2枚目をマナへ置いていた。
**マスターはそれを上書きした** —— 何も起こさなかったカードは、還元もせずに墓地へ行く。
したがって2枚目は「コスト2を払って何もしない」カードである。

実装は `SpellDisposition.TO_TRASH`(【還元】を働かせずに墓地へ)を新設して表した。
★他の2値と違い、これは行き先を**別の場所へ**置き換えるのではなく、
通常の行き先(墓地)を**置き換えさせない**ための指示である。

★**Batch 58 の試験が1件落ちた —— それが正しい。**
`Batch58ReworkTest.地脈の覚醒は同じターンに2枚目を使っても効果は発動しない` を
新しい裁定に合わせて書き換えた(消していない。`rework-triage.md` 5章)。

### 3-7. 黄泉の召喚主 —— ガードを恒久のルールへ(裁定275)

マスターは**狭い読み**を採った。「手札にあるかのように」は
「効果で場に出すのではなく**召喚**である」の念押しにすぎず、
墓地を手札と同じゾーンとして扱う(【特殊召喚】の代替コストや「手札の」を参照する軽減が乗る)
という意味ではない。したがって**実装は変えない**。

Batch 57 が置いた暫定ガード(対象を読む【召喚時】を持つミニオンは墓地から召喚できない)は
**恒久のルール**になった。

★**残っている問い**: 対象を読む【召喚時】を「選ばせずに自動決定(AutoChoice)で通す」形に
するかどうかは、まだ決まっていない。今は止める側を採る ——
黙って壊れる(NullPointerException で 500)よりは理由を返すほうがよく、
自動決定は「本人に選ばせる」原則(裁定192)から外れる選択なので、
実装で決めずに裁定を仰ぐ(**裁定278**)。

## 6. 積み残しと申し送り

### 6-1. ★英知の水晶で2つ、本文どおりに実装していない点がある

**(1) 「引いても良い」を問い合わせていない。**

マスターは「毎回問い合わせ(任意選択)」の形を承認したが、**実装できていない。**
割り込み選択(a9)は「効果の解決を中断し、再開点(`ResumePoint`)から続きを走らせる」仕組みであり、
**中断できるのは登録された再開点だけ**である。
ドローはこのエンジンのあらゆる場所から呼ばれる ——
ターン開始処理・スペルの解決の途中・【知識】の共通処理・破壊時の誘発……。
そのどこで中断しても、**中断された側の続き**を再開する術が無い。

当面は `AutoChoice.shouldDrawOptional`(山札が空でなければ引く)に寄せた。
《執念の暗殺者》の「引いてもよい」と同じ判断であり、`AutoChoice` のクラス説明どおり、
割り込みが一般化できた日には**呼び出し1行を差し替えるだけ**で問い合わせ式に移れる。

**(2) 「誘発によるドローは数えない」という制限を足した。**

両者が《英知の水晶》を場に出していると、A のドローが B に引かせ、
その B のドローが A に引かせ……と**互いに終わらない**。
本文には書かれていない制限だが、書かれたとおりに実装すると**ゲームが停止しない**ため、
規則として足さざるを得なかった。`GameActions` の再入ガードで表している。

★**どちらもマスターへ報告済みである。**(2) の読みは裁定を仰いでいる(**裁定279**)。
