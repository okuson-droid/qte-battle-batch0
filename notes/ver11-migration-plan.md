### 0-4. 構造面の重要な事実

- **manual-cards.json には `keywords` フィールドが無い**(24 hotfix2 で廃止・テキストが正)。
  通常モードのエンジンは構造化キーワード(RuleGuards の GUARD 判定等)を要求する
  → **ロード時にテキストからキーワードを抽出する層**が要る(決定的・テスト可能)。
- **通常モードはユーザーデッキを既に受け取れる**(`deckJson` → `DeckValidator`)。
  ID を一元化すれば**デッキメーカーで組んだ JSON がそのまま自動対戦で使える**。
- デッキのプリセット(DeckFactory)はカードIDのハードコード → 移行対象。
- 自動モードのロジック 4,242行に**テストがゼロ**のまま。★サンドボックスは Maven 403 で、
  わたしはコンパイルもテストも実行できない(構文走査のみ)。

## 1. Phase 0 の裁定(★2026-08-18 に D1〜D4 確定)

- **D1. カードマスタの一元化方式。→ ★案Bで確定。**
  - **案B(確定): 通常モードも manual-cards.json を正にする。** カードIDは `QTE-M-*` に
    統一し、`CardEffectRegistry` の既存119枚のキーは `ledgerCardId` 対応表で機械変換。
    `qte-cards.json` は退役。**正が1つになり(設計判断28)、デッキメーカーの JSON が
    そのまま自動モードで使える**。
  - 案A(却下): 台帳を235枚に拡張して2ソース維持 → 同期作業が永続する。
- **D2. 効果未実装カードの扱い。→ ★「印つきで入れられる」で確定。**
  デッキに入れられるが、面に「効果未実装」の印 + デッキ検証で警告。
  早い段階で全カードのデッキが組めて遊べる。ルール強制モードで効果が黙って
  不発になるのは誤解を生むので、印は必須。
- **D3. 進化(18枚+エンジン工事)をいつやるか。→ ★「後半に独立フェーズ」で確定。**
  まず非進化217枚で遊べる状態を作る(進化はそれまで D2 の印で保留)。P3(54〜55)で実施。
- **D4. ★【賢魂：n】のルール裁定。** → **★確定(2026-08-18 マスター裁定 = 裁定152)。**
  **賢魂：n を持つミニオンは、スペルとしても使うことができる。**
  - スペルとして使う場合のコストは **n**。効果は【賢魂：n】に続くテキスト。
  - **ミニオンとして召喚した場合、賢魂の効果は発動しない**(通常のミニオンとして振る舞う)。
  - スペルとして使う場合は**スペルのコスト軽減などの影響を受ける**(=その使用は
    ルール上「スペルの使用」として扱う)。
  - 近縁: デュエル・マスターズのツインパクト / シャドウバースのアクセラレート。
  - 実装上の含意: (1) 手札 UI に「ミニオンとして出す / スペルとして使う」の2導線が要る。
    (2) エンジンは「ミニオンカードのスペル使用」という新しいアクション種別を持つ
    (解決後はスペルと同様に墓地へ、ON_CARD_USED 等のスペル系トリガも発火、の想定。
    ここは実装バッチ P4 の設計解説で個別確認する)。
- **追加裁定(2026-08-18 マスター裁定 = 裁定153〜155):**
  - **裁定153.【起動：n】= 自分のメインフェイズ中、ターンごとに一回だけ、n マナを
    支払って発動できる。**(P1 で既存実装がこの3条件——メイン限定・ターン1回・支払い——を
    すべて守っているか点検する。)
  - **裁定154.【進化】の召喚素材は進化ミニオンの下に置かれ、場を離れるときは進化
    ミニオンと一緒に移動する。** 破壊時はともに墓地へ、手札に戻される場合はともに手札へ。
    (実装上の含意: 場のミニオンが「下に置かれたカードの束」を持てる構造が要る。P3 の
    エンジン設計の中核。)
  - **裁定155(D5). 英知の継承者の【守護】【知識】消失は Ver1.1 の意図どおり。**
    差分表シート⑤は解決済み。
  - **裁定156.【常在】の「ターンに一回」の細目(該当: ロロイヨ伯爵・妖ノ長・ストク)。**
    (1) ロロイヨの守護カウントと潜伏カウントは**独立**(ターン最大2ドロー)。守護+潜伏の
    両方を持つ1体が出たら**両方誘発**して2枚引く。
    (2) ロロイヨは**相手のミニオン**が場に出ても誘発する(テキストの字面どおり。
    「自分の」と書いていない誘発は両者を見る)。
    (3) 「ターン」は**毎ターンリセット**(自分のターンで1回・相手のターンで1回)。
    ストクは相手ターンの戦闘破壊でも回復する。
  - **裁定157.【進化】の追加細目(2026-08-18)。**
    (1) **進化ミニオンは出したターンからリーダーにもミニオンにも攻撃できる**
    (いわゆる召喚酔いなし)。
    (2) **進化元に「他のカードによって付与されていた効果」を引き継ぐ**(例: スペルで
    受けた Attack+1)。進化元のテキスト自身の効果は引き継がない。
    (3) **ただし常在効果によって付与されている修正は引き継がない**(例: 「自分の
    ミニオンすべて Attack+1」は、進化後のカードに常在が及ぶかで改めて決まる)。
    - 実装上の含意: 修正値を**個別付与(カードに紐づいて残る)**と**常在計算(オーラから
      毎回算出)**の2系統に分ける構造が必須。進化時に前者だけを新しい面へ移す。
    - P3 で個別確認する細目: 素材が2体以上のときの引き継ぎ(全素材分か)・素材の
      タップ状態や受けているダメージの扱い・「そのターンの間」付きの付与の残り方。
- **★Phase 0 の裁定はこれで全件確定(152〜157)。**実装中に新たな曖昧さが出たら、
  その都度バッチの設計解説で個別に裁定を仰ぐ。

### 2-1. ★【常在】と TriggerType の扱い(2026-08-19 に計画を修正)

当初は 47 を「エンジン語彙のバッチ」とし、【常在】フレーム(PersistentAura 拡張)と
不足 TriggerType をまとめて作る予定だった。**47 の着手時に20箇所を全部読んで、方針を変えた。**

- **【常在】は1つの仕組みではない。** 4つの別々の形の総称である ——
  (a) 評価するたびに場を見るもの(**既にこの形で動いている**。設計判断4)、
  (b) 場に居る間ずっと反応する誘発(トリガーの拡張)、
  (c) ターン開始時の自壊(`ON_TURN_START` が要る)、(d) 進化専用(P3)。
- **★`PersistentAura` は方向が違う。** あれは<b>期限</b>を型として持つ器であり、
  【常在】に期限は無い(条件は「場に居ること」)。状態として保存すると、場を離れたときに
  消し忘れる。保存しない = 既存のやり方がそのまま答えである。
- **足りない `TriggerType` は実質3つだけ**だった(未実装50枚を全部読んで数えた)。

**器を先に作っても、使い手のカードが1枚も無い状態になる。**(裁定167 の親戚: 使い手のいない
器は設計ではない。その形でよいかを確かめる材料が無いまま形が固まる。)
したがって **47 は「印」1本**とし、**トリガーは P2 の各文明バッチが必要になった時点で足す**。

★P2 で要る3つ(47 の調査結果。詳細は `notes/batch47-design-notes.md` 6章):

| 足すもの | 要るカード |
|---|---|
| `ON_TURN_START`(ターンのはじめ) | ハク霊 / コク霊(風) |
| 盤面全体のミニオン登場(自他を問わない) | ロロイヨ伯爵(水) / 英皇アントマルエル(光)。裁定156(2) |
| 場以外から自分の墓地に置かれたとき | カムバックキーパー(闇) |

**規模感: 9〜12バッチ。**P1 が終わった時点で「全カードでデッキが組めて対戦できる
(未実装は印つき)」になり、以後は効果の充足率が上がっていく形。進捗はレポートツールの
数字(未実装 n 枚)で常に見える。

## 3. ★最大のリスクと運用

1. **わたしは Java を実行できない**(Maven 403。構文走査のみ)。P1 以降は毎バッチが Java であり、
   **マスターの `mvn test` + コンパイル確認が各バッチの必須工程**になる。
   → バッチを小さく刻む・JUnit を先に書く(落ちたらどこかが分かる形)・
   可能ならサンドボックスの許可リストに Maven Central を足す検討を再度お願いしたい。
   これが通れば往復が桁で減る。
2. **作り直し69枚は挙動の変更**であり、遊び味が変わる。設計解説に新旧併記で残す。
3. **手動モードへの影響はゼロに保つ**(manual-cards.json は読むだけ。書き換えはしない)。
4. 既存 JUnit 7本(手動系)と検証518項目は全フェーズで維持。
